# 21. 2026-10-16/17 — Careers referral system (member referral codes)

**Owner:** *"make referral system on careers."* Built late 2026-10-16 → 2026-10-17; the session **crashed before committing or documenting**, so the 2026-10-17 recovery pass audited every artefact and committed it (daily log `2026-10-16.md`, tracker rows 59–60).

Every `/careers` account gets its own **unique 8-character referral code**, can share a `/careers?ref=CODE` link, and sees how many people signed up with it. **Attribution is fixed at signup and never editable** (owner ruling) — the profile card is display-only.

| Area | Detail |
| :--- | :--- |
| **`lib/careers-referral.mjs` + `.d.mts`** | The **single source of truth** for the code format. Pure ESM, zero deps, **isomorphic** — randomness comes from `globalThis.crypto.getRandomValues` (browser AND Node ≥ 19), so the **same module** is imported by the signup route (server validation) AND `AuthForms` (client bundle input filter) — no client/server drift. **Alphabet = 32 chars**: `A-Z` minus `I`/`O` and `2-9` minus `0`/`1` (no ambiguous pairs — safe to read aloud). **Length 8.** Exports `REFERRAL_ALPHABET`, `REFERRAL_CODE_LENGTH`, `normalizeReferralCode` (uppercase + strip non-`A-Z0-9`; deliberately **keeps `0/1/O`** so a bad code fails loudly instead of being silently mangled into a *different* code), `isValidReferralCodeFormat`, `generateReferralCode` (rejection-sampled; 256 % 32 === 0 → exactly uniform, no modulo bias), `generateUniqueReferralCode(isTaken, attempts=10)`. Hand-written `.d.mts` (types without a build step, same pattern as `lib/email-autoreply.d.mts`). |
| **Signup route** | (1) **Rate limiting added** — careers auth had **none**, while every other public write route has had one since 2026-10-08; per-IP **20/min** fixed window **before** parsing the body (env-overridable `CAREERS_SIGNUP_RATE_LIMIT`). (2) Optional `referralCode` is normalised + format-checked + **must exist on another account**, else `400 { code: 'INVALID_REFERRAL' }`. (3) Every new account gets its **OWN** unique code (collision-checked via `findOne`). (4) Persists `referralCode` + `{ referredBy, referredAt }` when referred. On a successful signup the `?ref=` param is stripped from the URL so a refresh cannot re-prefill it. |
