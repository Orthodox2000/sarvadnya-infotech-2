| **Brief** | Owner: the newly added **`public/er.png`** replaces the Diwali content, there is only one image so it must fit every width; keep the "stays until closed" behaviour for a first visitor; remove every Diwali reference; and **returning visitors see it 20 s after landing, only once**. Clarified in a follow-up: *"new visitor, popup at start, old visitor who don't have popup see it 20 s later, new visitors don't see 20 s later."* |
| **Files (renamed, not patched around)** | **NEW `app/components/GreetingPopup.tsx`** (was `DiwaliPopup.tsx`) · **NEW `lib/greeting-popup.ts`** (was `lib/diwali-popup.ts`) · `app/layout.tsx` (preload script + `id="greeting-preload"`) · `app/(site)/layout.tsx` (mount + import) · `scripts/check-demo-independence.mjs` (allowlist path updated, otherwise `ALLOWLIST DRIFT`). Both old files **deleted**; no `diwali` identifier survives in `app/`, `lib/` or `scripts/`. |
| **Asset** | `public/er.png` measured **1280×640**, PNG, alpha channel **fully opaque**, **540 KB**. Re-encoded once with sharp into a committed **`public/greeting-popup.webp` — 1280×640, 66 KB** (`resize(1280,640,{fit:'inside'}).webp({quality:82,effort:6})`). The PNG is untouched (owner master); the card loads only the WebP with `unoptimized`, so `/_next/image` never reads/re-encodes a 540 KB PNG on a cold request. Regeneration command sits in `lib/greeting-popup.ts`. |
| **Fit on every width** | ONE box for every breakpoint — no `matchMedia`, no second srcset, no desktop/mobile split: `aspect-[2/1] w-[min(90vw,160vh,56rem)]` + `object-contain`. So the height is always ≤ 80vh, the card is **324×162 px at the 360 px floor** and **896×448 px** from 1280 px up. `90vw` (not 92vw) because the overlay's `p-4` already takes 32 px at 360 px — 92vw would have overflowed the padded box by 3 px. `object-contain` means a future replacement of any ratio letterboxes instead of cropping or stretching. **This is the byte-identical rule the old WIDE artwork used from `md` up** (`er.png` is 2:1, exactly `diwali.png`'s 1920×960 ratio), so it is the proven fit rather than a new one — the only difference is that it now applies below `md` too, where the retired square asset used to be. |
| **Two timings, one flag** | New key `svd_greeting_2026`, written at **open time** (not close time — the ConsentBanner September bug). No flag → `reveal()` immediately. **Retired Diwali flag `svd_diwali_2026` present → `setTimeout(reveal, 20_000)`**, then the new flag is written, so it is once only. New visitors can never reach the delay branch (they are already flagged), which is the owner's "new visitors don't see 20 s later". Storage blocked (private mode) → treated as a first visit and simply cannot be remembered. |
| **Timer scope** | The decision effect is **mount-only** and reads `window.location.pathname`, not `usePathname`. `(site)/layout` stays mounted across client-side navigation, so 20 s is measured from the **landing page** — a visitor who keeps browsing still gets the card, instead of the countdown restarting on every route change. The timer is cleared on unmount. |
| **Preload** | `<head>` inline script kept, renamed `greeting-preload`. It now fires **only for a true first visit**: it returns early if *either* flag is set, so returning visitors download nothing before the 20 s mark. Same single-URL discipline — the preload `href` and the `<img> src` both come from `GREETING_ART.src`. |
| **Unchanged on purpose** | Scroll lock (+scrollbar padding compensate), Esc close, focus to the ✕ with `preventScroll`, backdrop click, `z-[100002]` above ConsentBanner, skip list for the checkout and demo-cart routes, light `bg-[#033B38]/30 backdrop-blur-[2px]` backdrop, removal recipe in the component header. |
