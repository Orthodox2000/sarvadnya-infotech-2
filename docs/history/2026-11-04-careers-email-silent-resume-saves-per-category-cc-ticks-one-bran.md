# 2026-11-04 — Careers email: silent resume saves, per-category CC ticks, one brand across every template, and the referrer named in the welcome mail

> Session-history detail. Index: [docs/HISTORY.md](../HISTORY.md)

---

| Area | Detail |
| :--- | :--- |
| **Brief** | Owner, in one message: saving a resume must send **no email at all** (not to HR, not to the candidate, and never the global CC); the global CC must stop applying to everything — each email config needs a **tick mark** and only a ticked category may trigger it; every email format must share the same branding, logo, header and footer; and the referral signup welcome mail must **name the person attached to the referral code**. |
| **Resume upload is deliberately silent** | `app/api/auth/careers/resume/route.ts`: the whole email block (company copy + candidate confirmation, which rode `sendEmailDirect` and therefore also the global CC) was **removed**, along with the now-unused imports. The route saves the Blob reference and returns `{ resumeUrl, resumeName }` only. Job **applications** are unchanged and still notify company + candidate from `app/actions/careers.ts`. The `buildResumeCompanyHtml` / `buildResumeConfirmationHtml` exports stay for tests and back-compat even though nothing calls them in the route. |
| **Per-category CC (opt-in)** | New setting **`EMAIL_CC_DESTINATIONS`** (JSON array of destination keys). `getGlobalCc(destination?)` in both repos now returns `null` unless **all four** hold: the master switch is on, the address is valid, the caller supplies a destination, and that destination is in the list. **Empty list = no CC anywhere**, which is the safe default and the behaviour of every existing install. `sendInternalFormCopy` gained a `destination` option (explicit option → `submission.destination` → `submission.formType`), `sendTemplatedEmail` a `ccDestination`, and `lib/email-queue.ts` forwards the stored job destination on both the first send and the retry drain, so a retry cannot forget which category it belongs to. The careers signup welcome passes `ccDestination: 'careers'`. |
| **Admin UI** | `sarvadnya-advanced/app/admin/email-config/page.tsx`: each destination row carries a **CC tick** (teal when ticked; while the master switch is off the tick is both **disabled and rendered unchecked**, so the UI can never look active when it is not — the stored selection is preserved and reappears when the switch is turned on); the section heading is now *"3 · Global CC (ticked categories only)"*, the copy explains tick-vs-switch, and a live summary line prints how many categories are ticked (or says the CC applies nowhere). Load/save round-trips the new setting; malformed JSON degrades to an empty list rather than throwing. |
| **One brand for every template** | New **`lib/email-brand.mjs`** + hand-written `lib/email-brand.d.mts` (pure ESM, zero deps, the house pattern) is the single source of the masthead (with logo), the footer band and the company block. `lib/email-autoreply.mjs`, `lib/email-careers.mjs` (`renderShell`) and `lib/email.ts` (`buildFormEmailHtml`, plus inline logo attachment) all render it, so an auto-reply, a hiring notification and an internal form copy can no longer drift apart. Company copies previously passed `logo: null` and showed a wordmark-only header; they now fall back to the hosted `/TallyCertificate.png`, so every careers mail carries the logo. |
| **Referrer named** | `app/api/auth/careers/signup/route.ts` looks the referrer up with `fullName` in the projection and passes `referrerName` to `buildAccountCreatedHtml`. The template adds a body sentence — *"You joined with the referral code `XXXX`, shared by **Name**."* — **and** a `Referred by` row in the code table, so the person/code link survives skimming. A blank or missing name omits both (no dangling row) and every value passes through `esc()`. |
| **Tests** | `scripts/careers-email-test.mjs` gained two blocks in section 7: the name renders in body and table, a hostile referrer name is escaped, and an absent/blank name omits the line entirely. `test:cart` / `test:payments` are untouched — no pricing, cart or verification code was in scope. |
| **Nested repo** | Both `lib/email-brand.mjs` and `.d.mts` were copied **byte-identical (LF)** into `sarvadnya-advanced/`, and its `lib/email.ts` / `lib/email-queue.ts` got the same destination-scoped CC and branded header/footer by hand (fork drift — never copied wholesale). Its `public/TallyCertificate.png` exists, so the inline logo loads there too. The pre-existing uncommitted change in `app/admin/payments/summary/page.tsx` was left alone. |

| **Don't break** | The global CC is **never** applied without a ticked destination — do not reintroduce a bare `getGlobalCc()` call that ignores the destination. Resume saves must stay silent; do not "restore" a courtesy email there without an explicit owner ask. `lib/email-brand.mjs` is the only place the masthead/footer may be defined. The referral line is optional by design: a missing referrer must never print `undefined` or an empty `Referred by` row. |
