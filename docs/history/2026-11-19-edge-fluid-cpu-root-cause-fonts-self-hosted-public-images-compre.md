| **Edge CPU — the finding** | `middleware.ts` is the ONLY Edge function in this deployment. Its old matcher `'/((?!_next/static\|_next/image\|favicon\\.ico).*)'` invoked Edge middleware for **every** non-`_next/static`/`_next/image` request — all 69 rasters, both 4–11 MB videos, 19 MB of brochures, `llms.txt`, every font, and every other `_next/*` request. All of that was billed as Fluid CPU in iad1 for logic that can only ever apply to documents and `/api/*`. Confirmed no other Edge deploy: 11 API routes carry an explicit `runtime = 'nodejs'` and Next 15's default IS nodejs; **`proxy.ts` is inert** — verified in `node_modules/next/dist/lib/constants.js` of the installed 15.5.29 that `MIDDLEWARE_FILENAME = 'middleware'` and there is no `PROXY_FILENAME` constant, so it is not built or invoked (do NOT delete it — it is the latent Next 16 landmine in AGENTS §2.4). |
| **Edge CPU — the fix** | Matcher now `'/((?!_next/\|favicon\\.ico\|.*\\.(?:png\|jpe?g\|gif\|webp\|avif\|svg\|ico\|woff2?\|ttf\|otf\|eot\|mp4\|webm\|mov\|m4v\|ogv\|pdf\|css\|js\|mjs\|map\|txt\|html\|json\|xml\|csv)$).*)'`. The extension list is deliberately explicit, not `.*\.[a-z0-9]+$`, so document slugs containing a dot (e.g. `/news/tallyprime-7.2`) still get the www 301 / legacy 410 / admin 404 behaviour. Expected effect: Edge invocations drop from every request to documents + `/api` only; the Node functions (which the owner reported as fine) are unchanged. **Verify in the Vercel dashboard after deploy** — no dashboard access here. |
| **Fonts — self-hosted, Google fallback kept** | `next/font/google` removed from `app/layout.tsx`. The two variable woff2 files are committed at `app/fonts/geist-latin.woff2` (29 KB, weight 100–900) and `app/fonts/playfair-display-latin.woff2` (38 KB, weight 400–900), downloaded from the exact URLs in Google's CSS and loaded with `next/font/local` under the same `--font-sans` / `--font-playfair` variables, so no page/tailwind edit was needed. Next emits them as hashed immutable `/_next/static/media` assets. Each `localFont` has a `fallback` list beginning with the Google family name, and `app/layout.tsx <head>` keeps a Google Fonts stylesheet + preconnects as a genuine network fallback; `next.config.js` `style-src` now allows `https://fonts.googleapis.com` for that one sheet (`font-src` already allowed gstatic). `app/globals.css` body/.font-playfair/.font-inter stacks spell the Google fallback out explicitly. |
| **Images — compressed** | New repeatable **`scripts/compress-images.mjs`** (`npm run optimize:images`, `--dry-run` supported) uses the sharp already locked transitively by Next 0.35.5. It detects the real format from the bytes (several legacy `.jpg` files are actually PNG), compares palette vs lossless PNG and keeps the smaller, uses mozjpeg q82 for JPEG and q82 for WebP, validates dimensions after re-encode, and only writes a smaller file atomically. Filenames are NEVER changed — they are referenced from TSX, Tailwind `bg-[url()]`, seeded Mongo documents, JSON-LD and email HTML. `website-thumbnail.png` and `video-thumbnail.jpg` are skipped (exact bytes/dimensions asserted by SEO work, immutable for a year). Result: **59 files, 68.5 MB → 20.7 MB (69.7 % saved)**; biggest: `housing society.png` 8.5→1.7 MB, `ba.png` 7.7→1.9 MB, `tssgold.png` 7.1→1.5 MB, `trainning.png` 6.6→1.5 MB, `tallytowa.png` 5.4→1.3 MB. |
| **Images — loading improved** | Generated `public/cardbg.webp` (14 KB) and `public/mobilebg.webp` (23 KB) from the 1.5 MB / 864 KB PNGs and switched the four `bg-[url()]` pages (`/cloud`, `/do-more`, `/products`, `/products/tallycapital`) to them — the new filenames also bust the one-year immutable browser cache on the old PNGs. Raw `<img>` tags in `/about`, `/team`, `/tutorials` and `/learn-sara/chat` gained `loading="lazy" decoding="async"` (above-the-fold heroes got `fetchPriority="high" decoding="async"` instead). Existing `next/image` pages already carried `sizes`/`priority` and were left alone. |

The single warning (`postcss-url-parser: Unable to find uri in 'background-image:url()'`) is pre-existing: `app/globals.css` contains no empty `url()` and this session's only CSS edits were `font-family` declarations. First build attempt **failed** with a JSX parse error — a `{/* CHANGE … */}` comment had been placed at expression level inside the `/about` hero ternary; moved it into the parent `<div>`'s children (the four WebP-background comments were already inside a parent element and compiled fine). No dev server was up, so the build ran in the working tree per AGENTS §2.1. |
