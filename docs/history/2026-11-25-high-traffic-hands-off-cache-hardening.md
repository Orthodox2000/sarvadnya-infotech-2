# 2026-11-25 — High-traffic hands-off window: long public caches, 24 h ISR, image TTL, enrichment kill-switch

> Session-history detail. Index: [docs/HISTORY.md](../HISTORY.md)

---

| Fact | Detail |
| :--- | :--- |
| **Ask** | Owner: *"i wont be upating stuff for anytime in next few weeks, so we need to prepare for high traffic and sustain all"*. This removes the freshness constraint that had kept several TTLs short. |
| **Principle** | With no admin edits planned, the cheapest CPU is the invocation that never runs. Vercel serves a CDN/ISR hit at 0 ms Active CPU; the 7-day report showed 41.3% CPU throttle and 25% cold starts, so each avoidable invocation is disproportionately expensive. Everything below is a TTL/ISR change — no page markup, SEO output or business logic changed. |
| **Public API cache** | `PUBLIC_API_CACHE` (used by prices, news, settings, content, partners, reviews, search, insights search, careers) raised from **1 h → 6 h**, SWR tail kept at 24 h. `PUBLIC_MODULES_API_CACHE` raised **6 h → 24 h**. `PUBLIC_TUTORIALS_API_CACHE` raised **5 min → 6 h** and its warm-instance memory TTL matched. `next.config.js` mirrors all three so the exact-path header rules override the blanket `/api/:path*` no-store rule. Restore the short values when admin updates resume. |
| **ISR** | `/news/[slug]` **1 h → 6 h** (161 CDN requests in 7 days, 91.9% hit — the misses are Node renders). `/news` listing got an explicit `revalidate = 21600` (it previously relied on Next's default). `/modules` and `/modules/[slug]` **6 h → 24 h**. Both `/tally-insights/[section]` and `.../[lesson]` **6 h → 24 h**. `dynamicParams` unchanged, so a genuinely new slug still renders on first request. |
| **Images** | `next.config.js` `images.minimumCacheTTL: 604800` (7 days). `/_next/image` was 135 requests / 88.9% cached in the CDN report; each miss re-encodes through sharp inside a Function. Local source assets are already immutable, so a longer optimizer TTL only avoids repeated work. If a file is replaced in place, bump its filename/query. |
| **Visitor enrichment lever** | `/api/identify` was the single largest CPU path (37 calls / 7 s). Its geo + reverse-DNS work already runs in `after()`, so the 204 is not delayed, but it still consumes CPU. Added an operational kill-switch: `VISITOR_ENRICHMENT=0` skips that optional enrichment entirely while the visitor ledger (session upsert, paths, UTMs — the owner's 70-visitor source) keeps working. Default `1` preserves current behaviour. Documented in `.env.example`. This is a Vercel env var change, not a code-default change. |
| **Unchanged on purpose** | `/api/identify` beacon frequency (raising the client throttle only delays path beacons, it does not reduce their count). AI/crawler user agents — most bot traffic is already CDN-cached; edge-blocking them trades CPU for search/AI visibility and needs an explicit owner decision. Money paths (`/api/cart/*`, Razorpay verification) keep no-store. |
| **Deploy checklist** | 1) Deploy this repo (public frontend). 2) Confirm the earlier static homepage snapshot (2026-11-25 entry) ships in the same deployment. 3) Optionally set `VISITOR_ENRICHMENT=0` in Vercel if CPU is still high. 4) Re-read the same Vercel path table after a few days; `/api/tutorials`, `/api/prices`, `/api/modules` invocations and `/news/[slug]` uncached renders should all fall. |
| **Trade-off** | Admin edits to prices, news, modules, settings, careers and tutorials will not appear for 6–24 h. The owner explicitly confirmed no updates for several weeks. `/api/revalidate` still invalidates the modules tag/paths immediately if needed. |
| **Data-layer cap found in build** | The owner then explicitly requested a build. Build 1 passed (61 s, 180 pages, types clean) but the route table still showed `/news` at 1 h and `/modules` at 6 h: Next caps a route's ISR at the shortest `unstable_cache` TTL it reads. `lib/mongodb-utils.ts` had `CACHED_CONTENT_SECONDS = 1 h` and `CACHED_MODULE_SECONDS = 6 h`; both were raised to 6 h / 24 h to match the route values. Build 2 passed (30.7 s, 180/180 pages, zero errors) and confirmed `/news` 6 h, `/modules` 1 d, insights 1 d, sitemap 6 h. No dev server was running during either build. |
