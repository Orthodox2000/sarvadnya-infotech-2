# 2026-11-20 (follow-up) — Vercel Fluid CPU: ISR on the two hot pages, public API CDN caching, bot-skip on /api/identify

> Session-history detail. Index: [docs/HISTORY.md](../HISTORY.md)

---

| Fact | Detail |
| :--- | :--- |
| **Ask** | Owner pasted a Vercel CPU report and asked to fix it: `/news/[slug]` used 19 s Active CPU for 33 hits (~575 ms/hit), `/modules/[slug]` 8 s across 71 hits, `/api/prices` 2.08 s for 7 hits, `/api/identify` 3.46 s for 13 hits. Owner then ruled: **revalidate 3600**; **no cross-repo admin revalidation webhook** (1-hour staleness accepted); cache **all** public read-only GET endpoints; include the `/api/identify` early 204 bot-skip. |
| **Root cause — pages** | `app/(site)/news/[slug]/page.tsx:11` and `app/(site)/modules/[slug]/page.tsx:50` both had `export const dynamic = 'force-dynamic'` while already exporting `generateStaticParams()`. Every bot/visitor hit cold-booted the Node function, reconnected to MongoDB and re-rendered from scratch. Confirmed there is no `opengraph-image.tsx` and `renderBody()` is a plain string split — the "markdown/OG generation" theory in the report does not apply. |
| **Root cause — news CPU multiplier** | `generateMetadata()` and `NewsArticlePage()` each called `getNewsBySlug(slug)`, and the page then called `getNews()`: three full-collection `find({}).toArray()` scans per hit. `getNewsBySlug()` enriches every document until it matches, and `enrichNews()` (`lib/news-utils.ts:94`) calls `readingTime()`, which splits the **entire body** of each article. `fetchNews()` enriches + sorts the whole archive again. That is the ~575 ms of synchronous Active CPU. |
| **Root cause — API caching** | `next.config.js` had a blanket `/api/:path*` rule setting `Cache-Control: no-store, no-cache, must-revalidate`, which defeated the per-route cache header on `/api/prices` and made every public GET invoke a Node function. Next applies the *last* matching header rule for a key, so exact-path allowlist rules after the global rule restore CDN caching. |
| **Pages — fix** | Both pages now export `revalidate = 3600` and an explicit `dynamicParams = true`; `force-dynamic` is gone. `generateStaticParams()` still pre-builds every known slug, and a brand-new admin slug renders on its first request. No `/api/revalidate` route was added — owner accepted up to 1-hour staleness for admin edits. |
| **News page — two drains removed** | Imported React `cache()` and wrapped the slug lookup as `getCachedNewsBySlug`, used in both `generateMetadata()` and the page: one Mongo query per render instead of two. Added **`getRelatedNews(excludeSlug, limit = 3)`** to `lib/mongodb-utils.ts`: projected `slug, category, title, date, readingTime, content`, `$nin` on the current + retired slugs, `.limit(limit + 1)`, then a JS filter (auto-derived slugs have no `slug` field so `$nin` cannot exclude them), a parsed-date sort matching `fetchNews()`, and `.slice(0, limit)`. `content` is in the projection **only** because `enrichNews()` derives `readingTime` from it — seeded docs do not store `readingTime`, so dropping it would silently turn every card into "1 min read"; it is stripped from the returned objects. |
| **Public API caching — fix** | New `lib/api-cache.ts` exports the single `PUBLIC_API_CACHE = 'public, s-maxage=3600, stale-while-revalidate=86400'` string. Applied to the **11** public read GET handlers: `prices, news, modules, tutorials, settings, content, partners, reviews, search, careers/visible, careers/list`. `next.config.js` gets the same allowlist as exact-path header rules *after* the global no-store rule; query strings (`?section=`, `?type=`, `?q=`) are part of the CDN key. `force-dynamic` removed from `/api/prices` and `/api/partners` (no-op on route handlers, confusing next to a public cache header). `/api/search` was the biggest hidden win — repeat queries no longer re-run three DB reads plus the LLM summary call. |
| **Deliberately NOT cached** | `/api/health` (live monitoring/timestamp), `/api/email/diagnostic` (already explicitly `no-store`), all `/api/auth/careers/*` and `/api/chats/*` (user/session-specific), `/api/cart/*` and `/api/demo/*` (payments), `/api/identify` (POST beacon), `/api/contact`, `/api/email/submit`, `/api/careers` root and other form routes. ⚠️ **Pre-existing issue found and fixed after the live checks:** `/api/careers` root used `find({})` and exposed hidden (`visible:false`) draft jobs, unlike `/api/careers/list` and `/api/careers/visible`. The endpoint was excluded from the cache allowlist, and after deployment verification both its queries (pre-seed and post-seed) were changed to `{ visible: { $ne: false } }`. The endpoint was kept rather than deleted: the frontend uses only `/api/careers/visible`, but `scripts/seed_careers.mjs` still documents the root GET. |
| **Live verification (2026-11-20, after push + 5 min)** | `curl -I https://sarvadnyainfotech.com/news/tally-partner-mumbai` → `x-vercel-cache: PRERENDER` then `HIT`; `/modules/cf-agencies` → `PRERENDER` then `HIT`; `/api/prices` → `MISS` then `HIT` (client-facing `cache-control: public` because Vercel strips `s-maxage`/`stale-while-revalidate` from the response while using them internally — the `HIT` is the proof). `/api/identify` is POST-only, so the suggested `curl -I` returns 405; a real `POST -A "Googlebot/2.1"` returns **HTTP 204 in ~0.4 s**, confirming the early bot exit. |
| **Full live sweep (after the careers-fix push went live)** | All **11** allowlisted routes probed twice: `news, modules, tutorials, settings, content?section=home_faq, partners, reviews, search?q=tally, careers/visible, careers/list` plus `prices` → every one `MISS` then `HIT`. Non-allowlisted `/api/health` and `/api/email/diagnostic` stayed `no-store, ... must-revalidate` / `no-store` with `MISS` — the blanket rule still holds, so the allowlist is not over-broad. Careers leak fix live: `/api/careers`, `/api/careers/visible` and `/api/careers/list` return byte-identical payloads (same MD5, 10633 bytes) — no hidden drafts. Rendered article HTML confirms `getRelatedNews()` returns **real** derived reading times (`4 min read`, not the "1 min" fallback) with correct slugs/categories/dates, validating the `content`-in-projection decision. |
| **/api/identify — fix** | Added `isIgnoredRequest(request)` + a deliberately narrow `BOT_UA_RE` early exit returning 204 *before* the rate-limit map, body parse, Mongo upsert and geo/reverse-DNS work. In-app browsers (WhatsApp/Telegram) are intentionally not matched. `recordVisitor()`'s ignored-IP gate remains the authoritative write guard. Also corrected the stale comment claiming `proxy.ts` adds a second 60/min/IP cap — it is dormant under Next 15 (AGENTS §2.4), so this route's in-memory limiter is the only one. |
| **Hydration / breakage review** | Static pass only: every edit is server-side (page segment config, Mongo helper, route-handler response headers, Edge header rules, server-side UA check). No client component, store, localStorage/window read, or rendered value changed, so there is no new hydration boundary. `getRelatedNews()` returns the same plain serializable fields the cards already used (plus the preserved derived `readingTime`). ISR pages still execute `VisitorProvider` client-side, so visitor stats keep counting even when HTML comes from the CDN. |
| **Verified** | Standing single-pass directive (§3): no build, dev server, typecheck, `check:*` or test suite run. Post-deploy dashboard check still needed: Fluid CPU on both page routes and the public APIs should collapse; confirm admin edits appear within the hour. |
