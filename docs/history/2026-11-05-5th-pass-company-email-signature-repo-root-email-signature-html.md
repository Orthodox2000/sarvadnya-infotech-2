| **Root cause of "images dont load"** | Not the HTML. The global `/(.*)` header rule in `next.config.js` sends **`Cross-Origin-Resource-Policy: same-origin`**, so Chrome refuses every `sarvadnyainfotech.com` image inside a page that is not itself same-origin — `net::ERR_BLOCKED_BY_RESPONSE.NotSameOrigin`, reproduced with Puppeteer against `file://`. Third-party Flaticon PNGs loaded in the same run, which is what isolated the cause to our own header. (Email clients fetch images server-side and never apply CORP; this only broke browser previews/pastes.) |
| **Fix** | `next.config.js`: two rules placed **after** `/(.*)` (a later match overwrites the earlier key — see the `/diwali.png` comment) that set `Cross-Origin-Resource-Policy: cross-origin` + `Access-Control-Allow-Origin: *` for exactly `/email-signature/:path*` and `/TallyCertificate.png`. Deliberately not widened to `/public`. Header changes only take effect after redeploy or a `next dev` restart. |
| **Icons** | Social + partner icons are the owner's supplied set, committed under **`public/email-signature/`** (WhatsApp, LinkedIn, Instagram, Facebook, YouTube at 44×44 monochrome `#16294F`; `tally-software`, `bizanalyst`, `nosky`, `otu` partner marks). All five social PNGs are square and are rendered **20×20 in `<td>`s with `font-size:0;line-height:0`** and `display:block` links, so no baseline gap, no stretch, no inherited line-height offset, and **10px** gutters (row width 140px — fits the 320px content box with room to spare). Base64 data URIs were rejected on purpose: Gmail strips them. LinkedIn points at `linkedin.com/company/sarvadnya-infotech-llp/` (the repo's `sarvadnyainfotech` URL 404s). |
