| **Acknowledgement receipt** | `email-templates/email-autoreply.mjs` (`buildClientAutoreplyHtml`) is no longer a generic thank-you: it now renders a **receipt of the submitted enquiry** — a "Your Enquiry" block with **Name, Email, Contact, Product, Date** rows plus the **Message** in a wrapping (never `nowrap`) cell. New options `email`, `contact`, `product`, `message`, `submittedAt`; the old `service` name is kept as a fallback for `product` so the preview script still works. Date is pre-formatted IST (`formatSubmittedAt()` in `lib/email.ts`). |
| **Latest left-aligned structure** | Refactored to the classic left-aligned table pattern already used by `email-signature.html` / `license-expiry-email.html`: white shell, real 24px spacer rows + 12px side gutter cells (never padding on a 100%-width cell → no Outlook horizontal scrollbar), `width="600" align="left"` card with `max-width:600px;width:100%`, inline CSS only (no `<style>` block). The shared masthead/footer from `email-brand.mjs` are reused with a new `align:'left'` option (default stays `'center'`, so internal/careers mails are untouched). |
| **Web Team footer + sender** | Body sign-off and footer note now read **"Sarvadnya Web Team"** (the brand rule of "Team Sarvadnya, never a person" is preserved). `lib/email.ts` adds `AUTOREPLY_SENDER_NAME = 'Sarvadnya Web Team'` and `withSenderName()` so Resend's `from` is `Sarvadnya Web Team <address>` (address validated first, then decorated). `AUTO_REPLY_FROM_NAME` env/setting overrides the name. Reply-to is pinned to `info@sarvadnyainfotech.com` with a valid-address fallback so a bad override can't drop it. |
| **Actually sent to leads** | Two blockers removed: (1) `AUTO_REPLY_ENABLED` now defaults **ON** (`'1'`, was `'0'`) — admin setting/env can still switch it off; (2) `sendEmailDirect()` in `lib/email-queue.ts` no longer returns early when the page has no configured internal recipient. Previously that path saved the enquiry (admin panel) and emailed **nobody** — the exact complaint. Now the internal copy stays destination-first/opt-in, but the acknowledgement always rides the same unique-`jobKey` claim whenever a sender exists. A skipped internal copy is recorded as `status:'sent'` (not `failed`) so the existing soft-retry still covers a failed acknowledgement. No-destination sidebar forms use `skipCompanyCopy:true` to keep their legacy save-only internal behaviour while acknowledging the lead. |
