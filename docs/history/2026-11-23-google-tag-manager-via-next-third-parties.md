# 2026-11-23 — Google Tag Manager via `@next/third-parties` (no manual `<script>`)

> Session-history detail. Index: [docs/HISTORY.md](../HISTORY.md)

---

| Fact | Detail |
| :--- | :--- |
| **Ask** | Owner wants Google Tag installed "the best way", using `@next/third-parties` to avoid slowdowns, console warnings and "weird notifications" (hydration errors, ad-blocker errors, Google consent/debug popups), and supplied the tag: `https://www.googletagmanager.com/gtm.js?id=GTM-NNQDM334` plus a `dataLayer`/`gtag` stub. |
| **Key decision — GTM, not GA4** | The supplied id is a **`GTM-…` container**, so the correct component is `GoogleTagManager` from `@next/third-parties/google`, not the `GoogleAnalytics` component in the owner's illustrative snippet. `GoogleAnalytics` would load `gtag.js` and expect a `G-…` measurement id; using it here would silently track nothing. `GoogleTagManager` also emits the required `{'gtm.start': …, event: 'gtm.js'}` push that the raw snippet omitted — without that event many container tags never fire. |
| **Why no hydration / render problems** | `GoogleTagManager` mounts through `next/script`, whose default strategy is `afterInteractive`: the loader runs after hydration, does not block first paint and does not mutate the server-rendered DOM. It renders no visible UI, so there is no layout shift. Nothing is placed in `<head>`; the component is a sibling of `<body>` directly under `<html>`, the documented App Router pattern. |
| **Why no debug console noise** | `GTMParams` has no `debugMode` field at all (verified in `node_modules/@next/third-parties/dist/types/google.d.ts`), so Tag Assistant / verbose logging cannot be enabled by accident. `debugMode` only exists on the GA4 component and was deliberately not carried over. No nonce is needed because the site's CSP already allows `'unsafe-inline'` for scripts. |
| **Why no dev-mode noise** | The mount is gated on `process.env.NODE_ENV === 'production'`. Ad blockers and the GA opt-out add-on block `googletagmanager.com` during local development and print red `ERR_BLOCKED_BY_CLIENT` errors that are easily mistaken for a hydration failure; dev builds now load no Google code at all. |
| **CSP — the part that would otherwise break silently** | `next.config.js` has a strict site-wide CSP, so hosts had to be allowlisted or every hit would be dropped with a console violation: `script-src` + `img-src` gain `www.googletagmanager.com` and `www.google-analytics.com`; `connect-src` gains those plus `region1.google-analytics.com` and `analytics.google.com`; `frame-src` gains `www.googletagmanager.com` and `tagmanager.google.com` for GTM Preview. Existing directives are untouched. |
| **Container id configuration** | `app/layout.tsx` reads `NEXT_PUBLIC_GTM_ID`, trimmed, falling back to the supplied `GTM-NNQDM334`. The id is public (it appears in the script URL), so the fallback makes a fresh deployment work immediately and the env var only needs setting to switch containers without a code deploy. Documented in `.env.example`. |
| **Files changed** | `package.json` + `package-lock.json` (`@next/third-parties@15.5.28`, pinned to the installed Next 15.5.x line — peer range `next ^13 || ^14 || ^15`), `app/layout.tsx` (import, id constant, production-only mount), `next.config.js` (four CSP directives), `.env.example`, this detail file, `docs/HISTORY.md`, the daily log and tracker. |
| **Unchanged** | No manual `<script>` was added anywhere, no `<head>` edits beyond what already existed, no `app/(site)/layout.tsx` change (Vercel Analytics + SpeedInsights keep their single mount there), no `GoogleAnalytics`/`G-…` id, no `debugMode`, no change to the consent banner, and no touch of the nested `sarvadnya-advanced/` fork. |
| **Not run** | Standing single-pass directive (root AGENTS §3): no build, dev server, typecheck or check suite was requested, so none was run. The package's declared API and `next/script` default strategy were read from the installed files; the CSP strings were checked by inspection. **Verify on the live domain after deploy:** one `gtm.js?id=GTM-NNQDM334` request per page, a `dataLayer` entry with `event: 'gtm.js'`, and zero CSP/`ERR_BLOCKED_BY_CLIENT` messages in the console. Local dev should show no Google requests at all. |
