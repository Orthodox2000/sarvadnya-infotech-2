# 2026-11-25 — Fluid CPU follow-up: gate `/api/tutorials` fetches, 5-minute cache, and why Tally Insights needs no DB change

> Session-history detail. Index: [docs/HISTORY.md](../HISTORY.md)

---

| Fact | Detail |
| :--- | :--- |
| **Ask** | Owner supplied Vercel CDN paths (requests + cache %) and Fluid Active CPU by path, then: *"look for what is causing more and we can put all insight data inside static array in data folder instead of having entire on db"*, then *"issue is it does show visitor increased and I can also track 70 visitors, so peak is justified but we need to optimised"*. |
| **Reading the CDN table** | The percentage is the **CDN cache hit rate**, not error rate. Static chunks/fonts/images are 70–98% cached, `/news/[slug]` 91.9%, `/tally-insights/[section]` 92.3%, `/_next/image` 88.9%. The 0% rows are Vercel ingestion beacons (50 + 43, not our functions), `/api/identify` (37), `/api/tutorials` (23) and two WordPress probe paths (already answered at the edge as 410 by `middleware.ts` `GONE_PREFIXES`). So **the 60% edge-request figure is mostly cached static assets and crawler traffic — it is not the CPU cause**. |
| **Reading the Fluid table** | Active CPU P75 228 ms, memory 258 MB / 2.05 GB, CPU throttle P75 41.3%, cold starts 25%. Top CPU paths: `/api/identify` 37 calls / **7 s**, `/api/tutorials` 23 / **3.4 s**, `/` 12 / **3.19 s**, `/api/prices` 11 / 2 s, `/contact` 10 / 1.74 s, `/news` 9 / 1.69 s, `/api/modules` 9 / 1.48 s, `/api/settings` 8 / 1.28 s. Since the peak is real traffic (~70 tracked visitors), the fix is **CPU per request**, not capacity. Cold starts + 41% throttle mean each avoidable invocation is disproportionately expensive. |
| **Tally Insights is already static** | `lib/learn-tally-curriculum.ts` is a committed TypeScript curriculum (`SECTIONS` + `LESSONS` + getters). Both routes import it directly, set `revalidate = 21600` and `dynamicParams = false`, and pre-render all sections/lessons. `lib/insights-search.ts` explicitly says *"no DB, no LLM and no client import"*. `/tally-insights/[section]` is 92.3% CDN-cached with only ~3 misses. Moving it into `data/` would be a file relocation with **zero CPU or DB benefit** and would add import churn; deliberately not done. |
| **Actual DB-backed learning data** | The separate `learning_content` collection (7 docs, `/api/tutorials`) is what the Sara modal matches against. It was deliberately `no-store` since 2026-11-21 because a 1-hour edge cache hid an admin-added video. Its 23 uncached invocations were the second-largest CPU bucket. |
| **Fix 1 — stop the site-wide fetch** | `QuickSupportModal` is mounted on every page while closed, and fetched `/api/tutorials` on mount. The effect now runs only when `isOpen` is true (and only once while tutorials are loaded), with a cancellation guard. `Productbar` no longer prefetches `/api/tutorials` on Learning hover/click. `/tutorials` and `/learn-sara/chat` still fetch on their own page views, which is intentional. |
| **Fix 2 — 5-minute cache** | Added `PUBLIC_TUTORIALS_API_CACHE` (`s-maxage=300, stale-while-revalidate=1800`) in `lib/api-cache.ts`, mirrored in `next.config.js` with an exact-path header rule placed last so it overrides the blanket `/api/:path*` no-store. `/api/tutorials/route.ts` now sends that header and keeps a 5-minute warm-instance memory cache so repeat edge misses do not re-read Mongo. Freshness degrades from "next load" to "within 5 minutes" — explicitly shorter than the 1-hour TTL that caused the 2026-11-21 complaint. |
| **Not changed** | `/api/identify` is the single largest CPU bucket but is feature-critical: it already skips bots/ignored IPs, rate-limits, sends the 204 before geo/RDNS via `after()`, and is the source of the owner's 70-visitor ledger. Raising its client throttle would drop recorded paths. `/api/prices` (59.1% cached, 2 s) keeps its 1-hour TTL because prices are money data. Bots are mostly served from CDN cache. |
| **Expected effect** | `/api/tutorials` should fall from 23 invocations to roughly the number of Sara opens + 5-minute cache windows; the homepage `/` and `/contact` drops come from the earlier static snapshot change (not yet deployed in this measurement). Re-check the same Vercel path table after deploy to confirm. |
| **Verification** | None run (single-pass directive §3; owner did not ask for build/lint/test). Manual review only. |
