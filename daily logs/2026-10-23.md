### §11 — Defect 1: five SVGs were malformed XML, so browsers refused to decode them

`tally-gst`, `tally-inventory`, `tally-career`, `tally-payroll` and `tally-reports` contained a **raw
`&`** in their text ("F11 > Statutory & Taxation > GST Yes", "Godowns & Batches", "BOM & Reports",
"Pay Heads & Structures", "Daybook & Registers", "Interview Q&A, ..."). A bare `&` is invalid XML,
and a browser will not render a malformed SVG **at all** — `<img>` stays blank.

The trap: the file is served perfectly. `curl -I https://sarvadnyainfotech.com/images/insights/tally-gst.svg`
returns **200 `image/svg+xml`**, so every HTTP/status check passes while the picture is empty. Only a
browser decode (`img.naturalWidth > 0`) proves it.

Fix: escape the bare `&` (`&amp;`) in the 5 files. All 15 SVGs now parse (`xml.etree`).

### §12 — Defect 2: step 4 sat exactly ON the card's bottom border

The shared 4-step template — card `1080x360` at `translate(60,200)` with rows at `cy` 80/160/240/320,
step title `cy+10`, detail `cy+40` — put the **last detail baseline at y=360**, i.e. the card's own
bottom edge. Measured text bottom = card bottom **+4px** → the last line crossed the border and read
as "cropped"/"underflowed". 11 files shared it.

Fixed by re-fitting the geometry (not by restyling):

| | Before | After |
| :--- | :--- | :--- |
| Card | `1080x360` (y 200–560) | **`1080x390`** (y 200–590) |
| Row `cy` | 80 / 160 / 240 / 320 | **71 / 147 / 223 / 299** (76px rhythm) |
| Card padding (top / bottom) | 61px / **−4px** | **47px / 47px** |
| Canvas margin (above / below card) | 40px / 70px | **40px / 40px** |

`latest-tally-prime` (3 rows, already safe) only grew to the same 390px card so every Insight card
now shares one height: 66px top / 76px bottom padding.

`erp9-vs-prime` had a related nit: the centred **"VS"** label at 42px was 45px wide in a 40px gap

### §14 — New permanent guard

## Session (4): the Tally Insights sidebar scrolls on its own, and its scrollbar is gone

**Owner:** *"tall-insight sidebar scroll when hovered irrespective of main page scroll size, currently,
i have to scroll to bottom of contnt for sidebar scroll, also i dont wall large scrollbar on sidbar, make

### §21 — What was actually wrong

Not a missing `overflow` — a **sticky element taller than the viewport**. The sidebar card was only
`lg:sticky lg:top-20`, so its height was whatever the 13-section list happened to be (**611 px** of
content, **699 px** card). On a viewport shorter than that, the bottom of the list sits below the fold and
**nothing can bring it into view**: the card is stuck, so scrolling the page does not move it, and there was
no inner scroll box. The only escape was scrolling the page far enough that the sticky element released —
which is exactly what *"I have to scroll to the bottom of the content"* described.

### §22 — The fix (desktop only)

| Layer | Change |
| :--- | :--- |
| Card (`TallyInsightsNav.tsx`) | `lg:flex lg:flex-col lg:max-h-[calc(100vh-6rem)]` — the height is now capped to the viewport minus the `top-20` (5 rem) offset and 1 rem of breathing room |
| Header rows | `lg:shrink-0` on the search block and the "All sections / N guides" row, so only the list shrinks |
| List (`#tally-insights-sidebar-list`) | new `insights-sidebar-scroll` class → `flex: 1 1 auto; min-height: 0; overflow-y: auto; overscroll-behavior: contain` |
| Scrollbar | `scrollbar-width: none`, `-ms-overflow-style: none`, `::-webkit-scrollbar { display: none }` — the owner asked for it hidden |

Everything above is inside `@media (min-width: 1024px)` in `app/globals.css` (plus the `lg:` utilities), so
the **mobile collapsible accordion is untouched** — below `lg` the panel stays a `grid-template-rows` box
with no viewport cap and no scroll container.

**Why `flex: 1 1 auto` and not `flex-1`.** `flex-1` is `flex-basis: 0`; inside an *auto-height* flex column
that makes the item's hypothetical height zero, so the card would size itself from the header rows alone and
the list would collapse. Measured both ways: with `flex-1` a one-line search result ("No guides match …")
had a **0 px** panel; with `flex: 1 1 auto` it keeps its natural **53 px**.

**Why `overscroll-behavior: contain`.** Without it, once the list reaches either end the wheel continues into
the page — the sidebar would appear to "hand off" mid-gesture. With it, the gesture stays in the list.
