### A. Production crash — `TypeError: c.expireAt.getTime is not a function` on `/api/identify`
Root cause: a DB re-import from a JSON dump (commits `54ae9c3` / `b81bc6f`) stored BSON `Date`s as ISO **strings**. `lib/visitors.ts` called `.getTime()` on a stored value and threw. `ip_cache.expireAt` strings also disabled its TTL index, so the cache grew unbounded.

- **New `lib/date-coerce.ts`** — pure `toDateMs(value: unknown): number` (Date | number | string | anything → number or NaN). Zero deps so plain `node` can test it.
- **Hardened call sites:** `lib/visitors.ts` (list-geo cache `hit.expireAt`, session `existingGeoAt`) and `lib/order-status.ts` `buildOrderTimeline` sort.
- **`scripts/date-coerce-test.mjs`** (`npm run test:dates`, 9/9 incl. the exact prod-crash regression) — wired into `test:all`.
- **`scripts/migrate-string-dates.mjs`** — idempotent, dry-run by default, `--apply`. **APPLIED to the live Atlas DB: 1,453 docs repaired** across `ip_cache` (546), `visitors` (862), `orders` (17), `email_queue` (1), `form_submissions` (2), `careers_users` (1), `careers_sessions` (2), `modules` (6), `reviews` (4), `partners` (6), `learning_content` (6). Post-apply verification: **0 remaining string dates**; `ip_cache.expireAt` TTL index `expireAfterSeconds:0` confirmed healthy again.
- **`news.date` deliberately NOT converted** — `lib/news-utils.ts` calls `date.trim()`, so it must stay a string.
- Ported the same hardening to the **nested** repo (`lib/date-coerce.ts`, `lib/visitors.ts`, `lib/status-history.ts` `buildTimeline`).
