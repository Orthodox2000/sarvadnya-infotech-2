# Daily Log — 5 September 2026

## Learn Sara "stock" → TSS-Renewal Bug Fix, Token-Saving Keyword Matcher & Double AI-Validation Tests

### 1. Bug & Root Cause (systematic-debugging)
- **Reported:** asking Learn Sara about "stock" returned a long TSS-renewal reply — completely out of syllabus.
- **Root cause:** `matchTopic("stock")` scored the Inventory topic only **2** (single word +2/word), below the `>= 5` threshold in `lib/sara-topics.ts`. The query therefore never matched locally and fell through to `/api/chat` (mode `learn`), where the LLM (Gemini → Groq) drifted into TSS content.
- **Confirmed** by importing `lib/sara-topics.ts` directly in Node 24 (native TS type-stripping): before the fix `stock → null`, `inventory → 27` (correct).

### 2. Fix — Deterministic Local Matcher (`lib/sara-topics.ts`)
- Added optional `keywords?: string[]` to the `Topic` type; `matchTopic` now scores each keyword hit at **+5** (same as an exact label hit) using a word-boundary + regex-escaped pattern (prevents short keywords like "keys" from over-matching inside "monkeys").
- Synonym lists per topic: Inventory (`stock`, `stock item(s)`, `items`, `goods`, `product(s)`, `godown(s)`, `batch(es)`, `reorder`, `barcode`, `bom`, `multi-location`, `warehouse`), GST (`gst return`, `gstr1/2b/3b`, `tax filing`, `e-invoice`, `eway/e-way bill`), Banking (`brs`, `cheque`, `bank statement`, `neft`, `rtgs`, `upi`, `reconcile`), Payroll (`salary`, `pay structure`, `pf`, `esi`, `attendance`, `payslip`, `employee`, `hra`), Reports (`report(s)`, `balance sheet`, `profit`, `cash flow`, `dashboard`, `ratio`), Shortcuts (`shortcut(s)`, `hotkey`, `keys`, `f4/f9/f12`, `alt g`, `ctrl a`, `ctrl f`), TSS (`tss`, `renew`, `renewal`, `subscription`, `serial number`, `manage license`).
- **Result:** `stock → Inventory Management (7)` — deterministic, **no LLM call, no TSS drift, zero token spend** for core-syllabus queries.
- **Health fix:** removed the duplicated "Keyboard Shortcuts" topic (the list was 8 entries, 7 unique topics — the duplicate could mask keyword results).

### 3. Prompt Guard (`app/api/chat/route.ts`)
- `LEARN_SYSTEM_PROMPT` TSS section: TSS/renewal/expiry/subscription topics are answered **only when the user explicitly asks**; never volunteered for stock/inventory/banking/payroll/GST/reports/shortcuts queries. Defense-in-depth for any unmatched query that still reaches the LLM — and it keeps residual LLM replies short (saves output tokens).

### 4. Regression Tests
- **`scripts/sara-topics-test.mjs` (NEW)** — deterministic, standalone, no server, no AI (imports the TS module via Node 24 native type-stripping). 20 cases: the `stock` bug, synonyms, TSS isolation (`renew` → TSS; `stock` MUST NOT hit TSS), other topics intact, short-keyword over-match guard (`monkeys` must NOT hit Shortcuts), topic-dedupe sanity. → **20/20 PASS**.
- **`scripts/sara-test.mjs` — double AI-validation suite (needs a running server):** builds the stock reply through production `/api/chat` (mode `learn`) **once**, then re-validates it with an **independent AI judge** — a strict neutral PASS/FAIL verifier (not the Sara persona, which blocks "act as…" role prompts), via Gemini `gemini-3.5-flash-lite` with Groq `openai/gpt-oss-20b` fallback. A deterministic backstop asserts the reply teaches inventory and contains **no** TSS markers. A TSS control test guarantees `tss renewal` still answers correctly.
- **Token budget (client requirement: save tokens):** judge input is the `compressReply(` output — `[[label|url]]` buttons + markdown stripped, truncated to 1,400 chars; `maxOutputTokens=64` (Gemini) / `max_tokens=128` (Groq); `temperature=0`; the stock reply is fetched once and reused (not regenerated per judge call). `SARA_AI_VALIDATE=0` skips the judge entirely (deterministic backstop still runs).
