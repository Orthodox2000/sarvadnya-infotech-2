## 5. Fluid CPU: ISR on the hot pages, CDN caching on public reads, bot-skip on /api/identify

Owner pasted a Vercel CPU report: `/news/[slug]` 19 s Active CPU / 33 hits (~575 ms each),
`/modules/[slug]` 8 s / 71 hits, `/api/prices` 2.08 s / 7 hits, `/api/identify` 3.46 s / 13 hits.
The earlier middleware matcher fix had already cut Edge CPU to under a minute / 12 h.

Root causes: both detail pages had `force-dynamic` despite already exporting
`generateStaticParams()`; the news page loaded the whole news collection three times per hit
(metadata lookup, page lookup, related posts), with `enrichNews()` word-counting every full
article body; and `next.config.js` applied `Cache-Control: no-store` to **every** `/api/*`
route, defeating even the header already set on `/api/prices`.

Fixes: both pages now use `revalidate = 3600` + `dynamicParams = true` (1-hour staleness for
admin edits was explicitly accepted; no cross-repo revalidation webhook). The news slug
lookup is wrapped in React `cache()` so metadata + page share one query, and the three related
cards come from a new projected, `.limit(3)` `getRelatedNews()` helper — `content` stays in the
Mongo projection only because seeded docs have no stored `readingTime` and `enrichNews()`
derives it from the body; it is stripped from the returned objects. New `lib/api-cache.ts`
holds one CDN header value applied to 11 public read GET routes; `next.config.js` repeats the
allowlist as exact-path header rules **after** the global no-store rule (Next uses
last-match-wins). `/api/identify` now returns 204 before rate-limit/parse/DB work for ignored
IPs and known crawler UAs. `/api/careers` root was left uncached because it uses `find({})`
and leaks hidden draft jobs — logged as a separate fix.

Verification: per AGENTS §3 no build/typecheck/check suite was run at code time. Live curl
checks against the deployed domain are being run after this push.
