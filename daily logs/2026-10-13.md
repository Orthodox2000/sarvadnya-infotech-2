### §C — ⚠️ `npm run test:all` had been silently red since 2026-10-09 (pre-existing; fixed here)

`scripts/api-test.mjs` decided *"do the admin routes exist in this repo?"* with a bare `fs.existsSync('app/api/admin')`. Git does not track directories, so after the first-party capture routes moved to `app/api/chats` + `app/api/drafts`, **`app/api/admin/chats` and `app/api/admin/drafts/[id]` survived as empty folders** (`git ls-files app/api/admin` = 0 files). `existsSync` therefore returned `true`, the branch flipped to *"admin routes exist → expect 200"*, and the deployed site's **correct 404** was counted as a failure. Because `test:all` is an `&&` chain, **every suite AFTER api-test had not run for four days** (`sara`, `sara-topics`, `cart`, `order-status`, `date-coerce`, `payment-limit`, `seo-links`) — a red suite with nothing real behind it, hiding a green suite that was not running.

Fix: the guard now collects **real `route.(ts|tsx|js|jsx)` files** recursively and only then expects 200 (honest in both repos, and independent of a tidy worktree); the empty leftover directories were removed. `npm run test:api` → 12/12 and the assertion now reads *"GET /api/admin/stats is absent in the public repo (404)"*.

```bash

# → inserted: 4, updated: 2, skipped(unchanged): 15, removed: 0, total 24 docs
```
