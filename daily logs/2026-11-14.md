# 2026-11-14

One session, two passes on the same screen. The admin dashboard was readjusted twice: first to put
the numbers that change daily above the fold and delete the modules that repeated them, then — after
the owner looked at it — to shrink every stat onto one screen and push payments and careers to the
bottom. Documented in both repos, logged here, and pushed.

---

## Session 1 — Dashboard readjusted: daily numbers first, dead modules removed

Owner brief (verbatim):

- *"the new dashboard for admin is good but all important stats are below and have to scroll and too
  much unwanted modules and few stats are ahead, readjust it."*
- Later: *"and also have a last updated tag on refresh button."*

### §1 — What was wrong

The dashboard built on 2026-11-13 had the right content and the wrong **order**. Reading top to
bottom it went:

1. Four tall KPI cards
2. A four-row "Needs attention" list, each row carrying a description line, beside a **System
   health** card
3. **Three groups of five lifetime tiles — 15 tiles** — several of which repeated Orders, Visitors
   and Revenue that were already on screen at the top
4. Recent orders, then recent leads
5. A Quick-links footer

So the numbers that change every day sat three screens down, while six modules carried data that
fits into two. A dashboard's order *is* the feature: whatever is first is what the owner actually
reads.

### §2 — The new order

| Position | Block |
| :--- | :--- |
| 1 | Compact header — system chip + Refresh |
| 2 | **One dense six-tile KPI row** |
| 3 | **Recent orders (2/3) + Needs attention (1/3)** |
| 4 | **Recent leads (2/3) + All totals (1/3)** |

### §3 — The KPI row

Six distinct numbers, each still a link to the screen that explains it:

| Tile | Goes to |
| :--- | :--- |
| Revenue | `/admin/payments/summary` |
| New leads · 24h | `/admin/submissions` |
| Orders today | `/admin/payments` |
| TSS pending | `/admin/tss-renewals` |
| Visitors · 24h | `/admin/visitors` |
| Chats · 24h | `/admin/chats` |

No number appears twice anywhere on the page any more. The tiles turned **horizontal** (icon ·
value · label · hint) at `text-base sm:text-lg` in `grid-cols-2 sm:grid-cols-3 xl:grid-cols-6`, so six
fit one row and nothing truncates at the 360 px floor.

### §4 — What was deleted, and the one card that replaced it

| Deleted | Why |
| :--- | :--- |
| **System health** panel | The header chip already shows service, database and version. |
| **Quick-links** footer | The sidebar is the navigation; a second copy is noise. |
| **Three 5-card lifetime groups** (`MetricGroup`) | 15 tiles, several repeating the top row. |

Their unique numbers collapsed into **one compact "All totals" card** — label · value · hint rows
(`MiniStat`, two columns): contact submissions, bug and issue reports, TSS renewals, job applications,
candidate accounts, chat transcripts, form drafts, FAQ entries, orders total, paid orders. Values read
`—` until the first fetch lands.

### §5 — Needs attention

The per-row description line was deleted and rows with `count === 0` are now **filtered out**
(`.filter(item => item.count > 0)`). What is left is a short action list instead of a four-row block
of zeros. When everything is zero the panel says *"Nothing needs attention right now."*, and the
count badge in the header only renders when there is something to act on.

### §6 — "Last updated" on the Refresh control

The timestamp used to be its own line under the header. It is now a **caption under the Refresh
button** — `Updated 18:32`, or `Not updated yet` before the first fetch — rendered as a sibling
`<span>` of the `<button>` inside a `flex-col items-end` wrapper. Sibling rather than child on
purpose: the text must not be clickable, and it should be read as plain status text by a screen
reader.

### §7 — Smaller refinements

- Page spacing `space-y-6 → space-y-4`; header title `text-3xl → text-2xl`; subtitle removed.
- Recent-activity rows `px-4 py-3 → px-3 py-2.5`.
- 10 px hint text moved `slate-400 → slate-500` — slate-400 on white misses AA at that size.
- Every tile keeps an `aria-label` / `title`, so a truncated hint is still readable on hover and by
  assistive tech. Focus rings unchanged.

**Result:** `sarvadnya-advanced/app/admin/page.tsx` 790 → **707 lines**.

## Session 2 — Follow-up: 14 mini tiles, payments and careers moved to the bottom

Owner brief (verbatim):

- *"also lot of important info is in below scroll, i dontt want payment or candidate on top, else
  ensure all stats are smaller on top without scroll on desktop."*

### §8 — What the follow-up was really about

Two separate complaints in one sentence:

1. **Still too much below the fold.** The six-tile row was denser, but it still dropped half the
   stats under it.
2. **The wrong numbers were on top.** The row was led by Revenue and Orders today — payment figures
   in the first thing an operator sees, while job applications and candidate accounts were buried.

The ask was explicit: not payment, not candidates, up top — and *all* stats visible without
scrolling on a desktop.

### §9 — The headline row is now 14 mini tiles

`StatCard` (icon · value · label · hint) was replaced by **`StatTile`** — **value and label only**, no
icon, no hint — in `grid-cols-2 sm:grid-cols-3 md:grid-cols-4 xl:grid-cols-7`. Fourteen tiles
therefore render as **two rows on a desktop**:

| | | | | | | |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Leads · 24h | Leads · 7d | Submissions | Bug reports · 24h | Bug reports | TSS pending | TSS renewals |
| Visitors · 24h | Unique visitors | Chats · 24h | Transcripts | Drafts · 24h | Form drafts | FAQ entries |

Every one is non-financial. Each still links to its own screen.

### §10 — Payments and careers off the top

Orders (total) · Awaiting payment · Paid orders · Revenue collected · Job applications · Candidate
accounts no longer appear in the headline grid at all. They live only in the bottom card, retitled
**"Payments & careers"** (was "All totals"), same compact `MiniStat` label · value · hint rows in two
columns.

### §11 — Page order, with leads before orders

| Position | Block |
| :--- | :--- |
| 1 | Header — system chip + Refresh + `Updated 18:32` caption |
| 2 | **14-tile stats grid** |
| 3 | **Recent leads (2/3) + Needs attention (1/3)** |
| 4 | **Recent orders (2/3) + Payments & careers (1/3)** |

Leads now come before orders, and the payment totals are the last thing on the page — so nothing
financial is above the fold, by construction rather than by luck.

### §12 — Signal colour

`StatTile` takes a `warn` prop. **TSS pending**, **Bug reports · 24h** and **Leads · 24h** render
`text-amber-700` when their count is non-zero; at zero they stay slate. The three numbers that imply
someone is waiting on you now look different from the three that are just information.

### §13 — Dead code cleaned out

Dropping the tile icons left the `ICONS` map with 11 glyphs and 2 users. It was trimmed to those two —
the Refresh spinner and the warning glyph in the error banner.

**Result:** `app/admin/page.tsx` 707 → **660 lines** across the two passes.
