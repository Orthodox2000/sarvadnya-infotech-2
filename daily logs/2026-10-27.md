### §1 - Why the chat was dead: TWO independent defects, both fatal on their own

Neither defect was a "revert" problem. The code was right; two configuration/seam assumptions were
wrong, and they masked each other.

**Defect A - Gemini was authenticating with the wrong header.**

`callGemini()` decided the auth mode like this:

```ts
if (apiKey.startsWith('AIza')) headers['x-goog-api-key'] = apiKey
else headers['Authorization'] = `Bearer ${apiKey}`
```

That `else` assumed "not an `AIza` key => an OAuth2 access token". Google now issues API keys in an
`AQ.` format, and this project's key is one of those - so every Gemini request went out as
`Authorization: Bearer AQ.…` and Google answered **401 "Request had invalid authentication
credentials"**. Every Gemini key was skipped on every single request, forever, silently.

Proven directly against the API with the project's own key:

| Header sent | Result |
| :--- | :--- |
| `x-goog-api-key: AQ.…` | **200 OK** |
| `Authorization: Bearer AQ.…` | **401** |

Fix: only a `ya29.` prefix is an OAuth2 **access token**. Everything else (`AIza`, `AQ.`, anything
else, including the default) goes in `x-goog-api-key`. A prefix test, not a substring test.

**Defect B - the Groq fallback was 413-ing on its own prompt.**

With Gemini skipping every request, Groq was the only provider left - and Groq's free tier is a hard
**8,000 tokens per minute** ceiling measured against the **whole request**. The sales system prompt had
grown to **44,466 characters (~10,300 tokens)**, so every Groq call was rejected with `413 Request too
large`. Key rotation cannot fix that (both keys share one org, so rotation adds zero throughput).

Result: Gemini 401 + Groq 413 = "AI service temporarily unavailable" on every non-cached question, and
the local keyword fallback answered instead. That fallback scored with **substring** matching, which is
§4's defect, so greetings hit product rows.

Both had to be fixed; fixing either alone still leaves the chat broken.

### §3 - Learn mode was asking for more tokens than the tier allows

`groqMaxTokens` requested **8,192** completion tokens in learn mode. On a ~4k-token prompt that alone
exceeds an 8,000 TPM ceiling, so **every** learn request was rejected regardless of the prompt shrink.

### §4 - History trimmed by token budget, not turn count

The old trim was `messages.slice(-MAX_HISTORY_TURNS)` - 24 turns. A turn count is not a budget: 24 real
turns pushed the request back over the wall even with the shrunk prompt.

`trimHistory(messages, budgetTokens)`:

- walks **newest -> oldest** keeping what fits `GROQ_INPUT_TOKEN_BUDGET = 6_200`,
- `estimateTokens = ceil(chars / 4)` plus 4 tokens of per-message overhead,
- **always keeps the last turn** and **never starts on an assistant turn**,
- the budget is what is *left* after the system prompt:
  `Math.max(600, 6_200 - estimateTokens(systemPrompt))`.

A 413 is still not retried (retrying it across keys is pointless), so it surfaces as HTTP 503 - the
thing to watch if the prompt ever grows again.

### §5 - The offline fallback was answering greetings with product rows

This is what the owner actually saw. `scoreItem()` used **substring** matching:

- `"how r u"` scored **7** against *"Show last purchase cost in sales"* - the label "Show" contains
  "how", the detail "Shows" contains it too.
- `"i dont ge tit"` scored on the `tit` inside `quan**tit**y`.

So a greeting cleared `minScore` and the fallback replied with a catalogue. Fixed in four ways:

1. **Word boundaries, not substrings** - `escapeRe()` + a cached `boundaryCache` regex per needle, so a
   visitor's word must be a whole word (`(^|[^a-z0-9])needle([^a-z0-9]|$)`).
2. **Stopwords** - question/grammar words (`how`, `what`, `is`, `the`, `you`, `get`, `give`, `hmm`,
   `thanks`, …) are dropped before scoring. Once a whole-word name hit became worth the full threshold,
   `"how r u"` started matching every guide titled "How to …".
3. **A whole-word NAME hit is worth 6** (the `minScore` threshold); a detail-only hit stays **2**. At 5
   the exact noun in a product title (`"batch expiry report"`) fell one point short and the fallback
   stayed silent.
4. **`singular()`** so `report`/`reports` and `invoice`/`invoices` match each other.

Measured after the change (all **0** - i.e. the fallback now stays out of the way and the AI answers):
`how r u`, `what?`, `i dont ge tit`, `hello`, `hi`, `thanks`, `ok`, `hmm`.

Still matching (no regression): `what is tss` -> TSS Renewal product + 2 guides;
`do you have container handling` -> shop item + module.

`npm run test:sara-catalog` -> **37/37**.

### §7 - Chat drafts now need a real email (the blank "Form Drafts" rows)

Owner: *"form draft too triggers automatically form ask sara even no actual email is found, ensure
proper regex matching exist before triggering form draft from ask sara"*.

Root cause: the chat tracker was started with **no fields**, and `flush('unload')` deliberately
**bypasses** the "nothing changed" early return. So every modal close and every page hide POSTed
`fields: {}`, and the admin screen gained a blank, unreachable row. A chat has no form to recover, so a
draft without a contact is noise, not a lead.

**One shared rule, two enforcement points** - new `lib/draft-contact.mjs` (+ `.d.mts`), pure ESM, zero
deps (house pattern: `rating-summary.mjs`, `sara-guard.mjs`, `careers-referral.mjs`), imported by BOTH
the browser tracker and the server route so the two sides can never disagree on what "valid" means:

| Export | Meaning |
| :--- | :--- |
| `EMAIL_PATTERN` / `isValidEmail(v)` | Deliberately stricter than `[^\s@]+@[^\s@]+\.[^\s@]{2,}` |
| `findEmail(fields)` | Scans **values**, not key names (different trackers name it differently) |
| `hasValidEmail(fields)` | Boolean form |
| `isChatEntryPoint(p)` | `ask-sara` / `learn-sara` |
| `shouldCaptureDraft(entryPoint, fields)` | The single gate: chat -> needs a valid email; everything else -> unchanged |

The old inline pattern accepted `a@b.c#`, `a@b..com`, `.a@b.com` and `a@-b.com`. The new one: local
part is dot-separated atext runs (no leading/trailing dot, no `..`), every host label starts and ends
alphanumeric, TLD is 2+ **letters**. All four are now rejected (`scripts/draft-contact-test.mjs`).

- **Client** (`lib/draft-tracker.ts`): the gate runs *before* the unload/blur bypass, on the merged
  `{...this.lastSent, ...this.pending}` view, so a field cleared later can never resurrect an old
  contact.
- **Server** (`app/api/drafts/flush/route.ts`): the same gate, so a stale cached client - or a direct
  POST - still cannot write the row. Non-chat entry points are untouched: a real form draft is captured
  progressively by design and gating it on a finished email would stop it capturing anything.
- `QuickSupportModal` now calls `onInput('name'|'email'|'phone')` at the capture stages - the chat
  tracker was previously never fed at all, which is the other half of why its drafts were empty.
- `app/(site)/learn-sara/chat/page.tsx`: the draft tracker was **removed entirely** - that screen has
  no form and could only ever POST `fields: {}`.

**A real defect the runtime probe caught.** The tracker POSTs only the **diff** after the first flush.
Chat sequence: flush `{name, email}` -> later flush `{phone}`. That second payload contains **no email**,
so the server gate refused it and the phone was **silently dropped** - the stored doc kept name+email
and never gained the number. The unit tests could not see it (the module was right; the caller was
wrong). Fix: when the diff alone is refused, the route reads the stored doc and re-checks
`{...carried, ...f}`. The lookup happens **only** on refusal, so an ordinary form draft still costs one
write and no read.

That also surfaced a second latent bug: the route did `$set:{fields:f}`, replacing the whole object on
every flush, so progressively captured field sets kept only the newest. It now merges as dotted
`fields.<key>` paths, and field **key names** are sanitised (`[^A-Za-z0-9_]` -> `_`, 64 chars) because a
key like `a.b` / `$x` becomes a Mongo path once merged.

Runtime proof `/tmp/opencode/verify-draft-gate.cjs` -> **20/20** against `next start` (spoofed public
`x-forwarded-for: 203.0.113.77`):

- 5 posts with no email / junk email (`''`, name only, phone only, `not-an-email`, `a@b..com`) ->
  `{ok:true, skipped:'no_contact'}` and **0 docs written**;
- valid email -> one merged doc, `status:'active'`, `expiresAt` ~30 days out;
- the diff flush **keeps** name+email and **gains** phone;
- a non-chat `contact` draft is **not** gated (name only -> written);
- dotted/dollar keys sanitised, no throw.

Cleanup: 3 probe docs deleted, 0 `zz-test` docs remain. Separate live check: `drafts` created in the
last 45 minutes = **0**, `drafts` total = **0** - the blank-row regression is gone.

`npm run test:draft-contact` -> **23/23** (20 core + 3 wiring assertions that pin the *callers*, since
the merge defect lived in a caller). Negative-controlled: reverting `{...carried, ...f}` to `f` makes
the wiring assertion FAIL; restoring makes it PASS. The suite is the last entry in `test:all`.

### §8 - Search Console failed indexing: the double-slash JSON-LD URLs

GSC listed ~10 "could not be indexed" URLs shaped like
`/news/tally-insights/gst-compliance/tally-gst`. Cause was in the code, not at Google's end:

`articleJsonLd()` prefixes `/news/` onto its `slug` (articles originally lived only there). The Tally
Insights lesson page passed its **full path** as `slug`, so the builder emitted

```
url / mainEntityOfPage: https://sarvadnyainfotech.com/news//tally-insights/<section>/<lesson>
```

`/news/` + `/tally-insights/…` = a double slash and a URL that has never existed. Google crawled the
advertised URL and correctly reported it. (This is exactly why `/sitemap.xml` was clean while GSC was
not - the sitemap builds URLs from `getAllLessonSlugs()`, the JSON-LD did not.)

Fix, three parts:

1. `articleJsonLd({ slug?, path? })` - **`path` wins over `slug`** and is used verbatim. `slug` stays
   the default for `/news` articles.
2. The lesson page now passes `path:`.
3. `next.config.js` gains `/news/tally-insights/:path*` -> `/tally-insights/:path*` (**permanent**, so
   Next emits **308**) so any already-crawled variant collapses onto the real page instead of 404ing.
   Verified live: `308` -> `http://127.0.0.1:3212/tally-insights/gst-compliance/tally-gst`.

Also added `/author/` to `middleware.ts` `GONE_PREFIXES` - `/author/admin/` was another WordPress
archive artifact still on the GSC list, and nothing on this stack serves `/author/*`, so **410 Gone** is
the honest answer rather than a redirect chain.

Sitemap re-checked on the rebuilt server: **104 `<loc>`**, **0** occurrences of
`sarvadnyainfotech.com//`.

### §9 - og:image was missing on 48 pages (a suppression bug, not a missing feature)

Found while verifying the pages GSC complained about. The 2026-10-12 work added
`app/opengraph-image.tsx`, but in Next.js a page-level `openGraph` object **without `images` replaces**
the file-based image instead of merging with it. `seoMetadata()` returns an explicit `openGraph`, so:

- `og:image` present on `/demo` and `/cart` (pages that declare no `openGraph` at all),
- `og:image` **absent on all 48 pages that call `seoMetadata()`** - i.e. the share card was inert
  site-wide.

Fix in `lib/seo.ts`: declare `images` (1200x630, `/opengraph-image`, alt kept in sync with
`app/opengraph-image.tsx`), mirror it into `twitter.images` (`summary_large_image` already), and add an
optional `image` param so a page can pass its own artwork - `/news/[slug]` now passes
`item.coverImage`. Local paths are resolved against `metadataBase`; absolute URLs pass through.

Verified on the rebuilt server: `og:image = https://sarvadnyainfotech.com/opengraph-image` with
`width 1200` on `/`, `/services/tss`, `/products/silver`, `/news/tally-tss-expiry-meaning` and

### §13 - Don't break

- **Gemini auth is a prefix test on `ya29.`** - never "anything that is not `AIza`". Google's `AQ.`
  keys are API keys and belong in `x-goog-api-key`.
- **`GROQ_INPUT_TOKEN_BUDGET` is a hard ceiling, not a target.** The shop catalogue ships names and 10
  links on purpose; re-adding 107 descriptions re-breaks every Groq request.
- **`lib/draft-contact.mjs` is the only place "valid email" is defined.** Do not reintroduce a local
  regex in the modal, the tracker or the route.
- **The server gate must merge the STORED fields before refusing.** The tracker posts diffs; without
  the merge, later fields are silently lost.
- **Non-chat drafts stay ungated.** A form draft is progressive by design.
- **`articleJsonLd()` takes `path` for non-`/news` articles**; a slash inside `slug` now fails
  `check:schema`.

  file-based share card on every page.
- **`stripComments()` must stay length-preserving** in `seo-audit.mjs`; the offset logic depends on it.
