# Daily Log — 29 July 2026

## Email Sending System (Built & Then Removed) + Admin Auth Refactor

### Workstream A: Email Sending Infrastructure (Later Removed)
Built a dual-path email sending system for the "Enquire Now" (`type='demo'`) form, then removed it entirely per user decision.

#### Files Created (later deleted)
| # | File | Purpose |
|---|------|---------|
| 1 | `lib/mail.ts` | Nodemailer SMTP transport via `mail.sarvadnyainfotech.com:587` (STARTTLS). Exports `sendEmail()` as fallback sender. |
| 2 | `lib/cpanel-mail.ts` | cPanel PHP mailer via HTTP POST to `cgi-sendmail.php` on `103.21.59.168`. Exports `sendEmail()` as primary sender. |
| 3 | `app/api/send-email/route.ts` | POST endpoint with rate limiting (5 req/min/IP), tries PHP first → falls back to SMTP → returns error. GET endpoint runs a diagnostic test against both senders. |
| 4 | `lib/rate-limit.ts` | In-memory sliding-window rate limiter (used exclusively by send-email). |
| 5 | `lib/api-security.ts` | Sanitization + validation utilities (`sanitize`, `isValidEmail`, etc. — used exclusively by send-email). |

#### Diagnostic Findings Before Removal
- SMTP server (`mail.sarvadnyainfotech.com:587`) accepted connections and returned messageId — emails never arrived in Gmail (inbox or spam).
- cPanel API (`UAPI` + `v2`) confirmed `send_email` function does not exist on this server — API approach was a dead end.
- Root cause determined: cPanel applies outgoing mail filters to external SMTP connections but not to local MTA submissions (used by Roundcube). Solution was a PHP `mail()` script on the cPanel server to use the same MTA as Roundcube.

### Workstream B: Admin Authentication — Stateless Token Rewrite
Converted admin auth from an in-memory Map-based session store to stateless cookie-based tokens.

#### Files Modified
| # | File | Change |
|---|------|--------|
| 1 | `lib/admin-auth.ts` | Rewrote `createSession()` / `getSession()` / `clearSession()` to use stateless `__admin_token` cookies (signed HMAC-SHA256) instead of in-memory Map. Added `validateToken()` / `generateToken()`. Eliminated server memory leak and enabled horizontal scaling. |
| 2 | `app/api/admin/login/route.ts` | Updated to use new stateless cookie-based auth. |
| 3 | `app/api/admin/session/route.ts` | Updated to validate `__admin_token` cookie instead of in-memory session. |
| 4 | `app/api/admin/logout/route.ts` | Updated to clear `__admin_token` cookie. |
| 5 | `proxy.ts` | Added `Cache-Control: no-store, no-cache, must-revalidate` to 401 response to prevent caching of auth failures. |
