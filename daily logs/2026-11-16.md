### §1 — The asset

| File | Size | Notes |
| :--- | :--- | :--- |
| `public/er.png` (owner upload) | 1280×640, 540,227 B | PNG, 2:1, alpha channel present but fully opaque — kept **untouched** as the master |
| `public/greeting-popup.webp` (new) | **1280×640, 66,070 B** | `sharp('public/er.png').resize(1280,640,{fit:'inside'}).webp({quality:82,effort:6})` |

Only the WebP is loaded. It is served by the existing `immutable, max-age=31536000` static-header
rule, and the card renders it with `unoptimized` so `/_next/image` never reads and re-encodes the
540 KB PNG on a cold request. 1280 px is already ~1.4× the largest CSS box (56 rem = 896 px).

### §2 — Fit on every width, with one image

There is no breakpoint any more. One box, whose ratio matches the artwork:

```
w-[min(90vw,160vh,56rem)]  +  aspect-[2/1]  +  object-contain
```

- height is always `w/2`, so it is never taller than **80vh**
- **324 × 162 px** at the 360 px floor, **896 × 448 px** from 1280 px up
- `90vw`, not 92vw: the overlay's `p-4` already consumes 32 px at 360 px, so 92vw would overflow the
  padded box by 3 px
- `object-contain` keeps a future replacement of any ratio fully visible (it letterboxes instead of
  cropping or stretching)

The previous `matchMedia` art-direction swap (square below `md`, wide above) is gone with the second
asset — it existed only because there were two artworks.

### §3 — Two timings, one flag pair

| Visitor | Behaviour |
| :--- | :--- |
| No `svd_greeting_2026` and no `svd_diwali_2026` — **new** | card opens immediately on mount, stays until the ✕, a click outside, or Esc |
| `svd_diwali_2026` set (saw the old card) — **returning** | `setTimeout(reveal, 20_000)` — card opens 20 s after landing, once |
| `svd_greeting_2026` set — **already seen this card** | nothing, ever |

A new visitor can never reach the 20 s branch: `svd_greeting_2026` is written by `reveal()` before
any timer could be considered, and it is written at **open** time rather than close time (the
ConsentBanner September bug: navigating away mid-show must not replay the card).

Storage blocked (private mode) → treated as a first visit; it simply cannot be remembered.

The effect is **mount-only** and reads `window.location.pathname`. `(site)/layout` is not remounted by
client-side navigation, so the 20 s is measured from the landing page — a visitor who keeps browsing
still gets the card, instead of the countdown restarting on every route change. It is cleared on
unmount.

### §4 — Two safety details carried over and one added

- The skip list (checkout and demo-cart routes) is still checked at mount. **Added:** it is checked
  again inside `reveal()`, because a returning visitor can navigate onto a payment form during the
  20 s countdown. Bailing there does not write the flag, so they still get the card on a later visit.
- Scroll lock, Esc close, focus to the ✕ with `preventScroll`, backdrop click, `z-[100002]` above
  `ConsentBanner`, light `bg-[#033B38]/30 backdrop-blur-[2px]` backdrop: unchanged.

### §6 — Preload

`<head>` still carries the inline preload, renamed `greeting-preload`. It now returns early if
**either** flag is set, so it fires only for a true first visit — a returning visitor downloads
nothing before the 20 s mark. The `href` and the `<img src>` both come from `GREETING_ART.src`, so
the two can never drift into a double download.
