### Part C — resume-upload bug found by the requested "test account creation + resume upload"

`/api/auth/careers/resume` only read a multipart **`resume` File**, but `ResumeManager` uploads the
PDF through the public chunked endpoint (`/api/upload/chunk` — required because Vercel rejects
bodies >4.5 MB) and then posts back **`resumeUrl` / `resumeName` / `oldUrl`**. So the register call
returned **400 "No file uploaded"** and the resume was **never saved** — the chunk upload succeeded
but the profile never recorded it (leaving an orphan blob). Fixed in
`app/api/auth/careers/resume/route.ts` to **accept both shapes**:

- `resume` File present → the previous direct-upload path (`persistResume` = Mega when configured, Blob otherwise).
- else `resumeUrl` present → use it, after a **trust check that the host is our Blob store**
  (arbitrary external URLs are rejected 400). Deletes the previous resume blob when it changed,
  and forwards to Mega when enabled.

### Vercel upload limits — finding

The user's concern resolves to a limit the chunk system **already** handles:

- **Binding constraint:** Vercel Functions cap the request body at **~4.5 MB**
  (`FUNCTION_PAYLOAD_TOO_LARGE`). The existing system (≤3 MB single multipart POST, larger files
  sliced into 2 MB chunks → temp blob parts `sarvadnya-uploads/_chunks/…` → server-side
  stream-concat on the final chunk) is exactly the right shape and is intact in both repos.
- **Per-plan quota (not per-request):** Vercel Blob on Hobby = 1 GB storage, 10 GB transfer,
  **2,000 advanced operations/month**; each chunk + the list + the final put + the part deletes
  costs advanced ops. Resumes are small, so usage is well inside quota.
- **No code change was needed** — the review confirmed the chunk path is present and in use.
