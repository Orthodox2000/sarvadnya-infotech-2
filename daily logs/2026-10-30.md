# 2026-10-30

## Session: context-surface reduction - `AGENTS.md` split from 354 KB to 20 KB so sessions stop hitting rate limits

Owner brief (condensed, in the owner's words):

- *"i want you to optimise directory as we are constantly hitting rate limit, ensure large files are not
  appended and context doesn't go out of hand"*
- Standing directive recorded this session: *"Act strictly as a single-turn code generation assistant. Do
  not invoke external linting agents, do not run iterative build checks, and do not call automated skills
  unless explicitly requested. Provide the design code directly."*

No application code was touched. This session changed the **instruction surface only**.

---

### §1 - Root cause, measured

`AGENTS.md` was **354,753 B / 1,336 lines**, and it is auto-loaded into context on **every single turn** of
every session - before a single file is read. That is roughly **~89k tokens of fixed cost per turn**. On a
per-minute token budget that alone can starve a session; in a long session it is a guaranteed window
exhaustion.

Measured internal layout of the old file:

| Region | Lines | Bytes |
| :--- | :--- | ---: |
| Hero header | 1-4 | ~130 |
| §1-§14 (architecture reference) | 5-319 | 87,742 |
| §15-§34 (session history) | 320-1310 | 179,114 |
| `## Developer Guidelines` | 1311-1334 | ~1,600 |
| `*Last Updated` changelog footer | 1335-1336 | **81,679** (one line) |

Largest individual histories: §27 (27,324 B), §12 (17,634 B), §34 (15,969 B), §31 (15,753 B), §33
(15,664 B), §32 (15,082 B). Largest reference block: §3 Key Components Catalog (11,919 B), §6 Email
(11,876 B), §11 `/demo` (11,725 B), §10 Nested Admin (10,280 B).

**~74% of the file was history.** History is valuable, but it is read once, when someone is working on that
area - it does not need to be in every turn.

### §2 - What was done: relocated, not trimmed

The prose was **not rewritten and not deleted**. Deleting it would have destroyed the reasoning behind every
rule in the file, which is the whole point of the file.

| New file | Content | Bytes |
| :--- | :--- | ---: |
| `docs/ARCHITECTURE.md` | §1-§14 verbatim + a `## Appendix — verbatim originals` holding the four original headings and the nine Developer Guidelines bullets | 90,844 |
| `docs/HISTORY.md` | §15-§34 verbatim, then `## Change Log (chronological, newest first)` containing the old changelog footer and the new 2026-10-30 entry | 263,932 (before this entry) |
| `AGENTS.md` (rewritten) | A distilled constitution: what the project is, the non-negotiables, the working mode, the developer guidelines, the codebase rules that bite, the commands, and a §-number index into the two `docs/` files | **20,259** |

`AGENTS.md` keeps every rule that **changes behaviour** (build/dev collision and the isolated-copy escape
hatch, kill-by-PID, Node version, lockfile-is-truth, Next 16 / `proxy.ts` landmine, no dev database +
`isIgnoredIp()` gate, server-authoritative pricing, HMAC-only verification, fail-closed `RAZORPAY_MODE`,
webhook idempotency, return policy never published, the three permanently-omitted structured-data fields,
nested-repo hand-port + CRLF rules, `tsconfig` `exclude` trap, dual-remote push discipline, teal brand and
WhatsApp green, 360 px floor and the navbar width budget, no `node:crypto` in client components, hydration

`GROQ_INPUT_TOKEN_BUDGET`, ASCII-only seeds, exactly-once email ledger, chat-draft email gate) and points at
the §numbers for the reasoning.

### §3 - Lossless, verified by diff

### §5 - Correction: `GEMINI.md` is NOT a duplicate of `AGENTS.md`

An earlier assumption in this session was that `GEMINI.md` was a 148 KB copy of the old `AGENTS.md`. It is
**not**. Measured: it is a **per-version changelog** - `# Project Conventions` / `## Versioning` / then ~100
`## Recent Changes (v1.1.399)` … `(v1.1.3xx)` sections - and it contains **0** occurrences of the old
AGENTS section titles. It is loaded by **Gemini CLI only**, not by opencode.

Therefore its text was **left untouched**. It was only added to `.opencodeignore` so it cannot be pulled into
an opencode turn by an incidental glob or read. If the project ever wants one history, the right move is to
fold those `## Recent Changes` entries into `docs/HISTORY.md` - not to delete them.

### §6 - Result

| Metric | Before | After |
| :--- | ---: | ---: |
| Always-loaded instruction surface | 353,626 B | **20,259 B** |
| Fixed tokens per turn (÷4 est.) | ~88,400 | **~5,100** |

The saving compounds: a 40-turn session no longer re-reads ~3.3 M tokens of the same prose.

### §7 - Rules this session added

  `docs/HISTORY.md`, never into `AGENTS.md`.
- `AGENTS.md` §7 is a §-number index into `docs/ARCHITECTURE.md`, so an agent can fetch only the section it
  needs instead of the whole file.

- The working-mode directive is recorded in **both** `AGENTS.md` §3 (auto-loaded) and `.gemini/MEMORY.md`
  (local, gitignored), with explicit precedence over "Validate Before Completing" and the build discipline.
