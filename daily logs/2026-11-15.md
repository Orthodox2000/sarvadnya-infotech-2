## Session 1 — The "last updated" caption was pushing the Refresh button off the line

Owner brief (verbatim):

- *"last refersh ti e takes refreshbutton out of line , readjusy ot"*

### §1 — What was actually wrong

The timestamp added on 2026-11-14 was stacked **under** the Refresh button:

```text
                        ┌──────────────┐
  [● System operational]│ ⟳  Refresh   │   ← button lifted ~7px above the chip
                        └──────────────┘
                          Updated 18:32
```

The caption lived in a `flex flex-col items-end gap-1` column so it sat below the button. That column
was then roughly **14 px taller** than the system-status chip beside it, and because the header row is
`items-center`, the extra height was split evenly — the button was pushed about **7 px up** out of
line with the chip. The tag was also costing a whole second line of header height for four characters
of text.

### §2 — The fix

The column became a **row**:

```text
  [● System operational | DB connected | v1.1.390]   Updated 18:32  [ ⟳ Refresh ]
                                                     └─ one centre line ─┘
```

| Change | Why |
| :--- | :--- |
| `flex flex-col items-end gap-1` → **`flex items-center gap-2`** | The wrapper is now exactly as tall as the button, so the chip, the caption and the button all sit on one centre line. |
| Caption moved **before** the button | The cluster is right-aligned. On the right, a changing timestamp (`Not updated yet` → `Updated 18:32`) would grow rightwards and shift the button leftwards. On the left it grows into free space and the button never moves. |
| Button padding `py-2.5 → py-2` | 36 px → 32 px, matching the chip. Before this, even without the caption the button overhung the chip by 2 px at top and bottom. |
| Caption + button kept inside their **own row**, not as bare siblings | The header is a `flex-wrap` container. As bare siblings the timestamp could be stranded on its own line above the button at a narrow width; as one row they always wrap together. |
| `shrink-0` on the button, `whitespace-nowrap` on the caption | The button must not be squeezed when the row wraps, and the date must not break mid-value. |

The caption is still a sibling `<span>` **outside** the `<button>` — not clickable, and announced as
plain status text rather than as part of the button's label.

### §3 — Width check

Measured arithmetically at the three breakpoints the header has to survive:

| Width | Result |
| :--- | :--- |
| ≥ 1024 px | Everything on one line — title left, chip + caption + button right. |
| 640 px | Chip drops to its own line (the version segment hides at `md`, the DB segment at `sm`); caption + button stay together. |
| 360 px (the floor) | Chip on one line, caption + button (~198 px) on the next. No horizontal overflow. |
