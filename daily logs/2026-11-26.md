## 4 — Dynamic social links for the signature and the other email templates

Owner: *"update signature template and rest template as well ... social media links dynamic ...
static fixed route with fixed output ... change server data but don't hardcode ... API call and we
send response ... must work on all email provider client, else make fixed reply string, ensure it
will work."*

- Design driver: mail clients never run JS or call APIs. The API call therefore runs in the
  **browser at copy time**, before the table is pasted; the pasted mail carries plain `https`
  hrefs, which every client supports. Baked-in hrefs remain as the fixed reply string.
- New `GET /api/social-links` (`app/api/social-links/route.ts`): fixed path, fixed JSON shape
  `{whatsapp, linkedin, instagram, facebook, youtube}`, plus `OPTIONS`. CORS/CORP relaxed and
  5-minute edge cache; `next.config.js` adds a last-position header rule so the blanket
  same-origin CORP and `/api/*` no-store rules cannot override it.
- New `lib/social-links.ts`: single server resolver with URL validation (http(s) only),
  WhatsApp phone normalising, fallbacks derived from the committed `STATIC_SITE_SETTINGS`
  snapshot, and a try/catch that always returns something. `lib/api-cache.ts` gained
  `PUBLIC_SOCIAL_LINKS_API_CACHE`.
- Four templates updated (`email-signature.html`, `license-expiry-email.html`,
  `license-expiry-email-copy-paste.html`, `diwali-email.html`): four `data-social` anchors each
  plus an identical resolver script outside the table (3 s abort, URL validation, no-op on any
  failure). Facebook stays unlinked per the 2026-11-20 owner ruling. README documents it.
