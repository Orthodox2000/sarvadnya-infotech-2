# Daily Log — 31 July 2026

## Vercel Chunked Upload System + Search Polish + Service Page Re-Skin (AMC Template)

### Workstream A: Chunked Upload System for Vercel Hosting

**Problem:** Vercel serverless functions reject request bodies over ~4.5 MB. Any single-shot `multipart/form-data` upload of a large image or PDF failed silently on the deployed site ("payload large" issue). The resume path was especially at risk (client allowed up to 5 MB PDFs).

**Solution:** Files are now broken into small chunks client-side (each request well under the 4.5 MB limit). Chunks are stored as temporary Vercel Blob parts; the final chunk triggers server-side streaming concatenation into one assembled blob, cleanup of temp parts, and deletion of the replaced file.

#### Files Created
| # | File | Purpose |
|---|------|---------|
| 1 | `lib/chunkUpload.ts` | Server-side chunk handler shared by both routes. Small files (≤1 chunk) upload directly. Multi-chunk uploads: each chunk stored as `sarvadnya-uploads/_chunks/{uploadId}/part-NNNNN.ext` (zero-padded, `allowOverwrite: true` for idempotent retries). On final chunk, lists all parts, validates count against `totalChunks`, streams them in pathname order into the final `sarvadnya-{type}-{name}-{timestamp}{ext}` blob via `@vercel/blob` `list`/`get`/`put`/`del`, deletes temp parts and the old blob (`oldUrl`). Guards: `MAX_CHUNK_SIZE` (3 MB per chunk), `MAX_CHUNKS` (200 → ~400 MB ceiling). Uses Node runtime + `maxDuration = 60`. |
| 2 | `lib/uploadClient.ts` | Client-side chunking helper `uploadFileChunked()`. Files ≤ 3 MB (`DIRECT_UPLOAD_LIMIT`) go in one multipart POST; larger files are sliced into 2 MB (`CHUNK_SIZE`) chunks and sent sequentially with `uploadId` / `chunkIndex` / `totalChunks` metadata. Returns `{ url }`. Optional `onProgress` callback. |
| 3 | `app/api/admin/upload/chunk/route.ts` | Admin-protected chunk endpoint (matches `/api/admin/*` proxy auth + multipart Content-Type validation). All 5 admin image uploads route here. |
| 4 | `app/api/upload/chunk/route.ts` | Public chunk endpoint (rate-limited by proxy) used by the career resume upload from the public careers page. |

**Notes**
- Legacy single-shot `/api/admin/upload` route left intact (backward compatible); new admin pages no longer call it.
- Vercel Blob's built-in native multipart (`uploadPart`) was rejected because it requires ≥ 5 MB parts, which conflicts with the 4.5 MB request-body limit — hence custom chunking + server-side concatenation.
- Assembly happens only on the final chunk; orphan parts from abandoned uploads are a known accepted edge case.
- **TypeScript build:** Clean (`tsc --noEmit`, full `next build` passed — both new routes present in the route table).

### Workstream D: Sara Chat API — 503 Bug Fix (Corrupted Groq Model Names)

**Problem:** `scripts/sara-test.mjs` run against production (`sarvadnya-infotech.vercel.app`) produced 13 failures across Ask Sara, Learn Sara, conversation context, and topic matcher — every AI-backed test returned `503`. Only the request-validation and injection tests passed.

**Root cause:** Commit `924f35b` ("sara new") introduced corrupted model names in `app/api/chat/route.ts`:
- `PRIMARY_MODEL = "llopenai/gpt-oss-120b"` — stray "ll" prefix; valid Groq ID is `openai/gpt-oss-120b` (confirmed against `app/api/ai/strategic-insight/route.ts` and the 2026-07-03 daily log).
- `FALLBACK_MODEL = "ama-3.3-70b-versatile"` — missing leading "ll"; valid Groq ID is `llama-3.3-70b-versatile`.

Groq returned 404 for the nonexistent model IDs, so every API-key attempt failed and the route fell through to `return NextResponse.json({ error }, { status: 503 })` (`app/api/chat/route.ts:214`). Validation tests still passed (they never reach the Groq call) and injection tests passed (answered locally before the AI call).

| 1 | `app/api/chat/route.ts` | Fixed `PRIMARY_MODEL` → `"openai/gpt-oss-120b"` and `FALLBACK_MODEL` → `"llama-3.3-70b-versatile"`. |

**Verification:** Local dev server confirmed both modes return `200` with real AI responses (Ask = TallyPrime Silver pitch; Learn = GST setup walkthrough).
