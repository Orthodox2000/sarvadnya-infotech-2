# 2026-10-26

## Session: GSC structured-data cleanup + a line-by-line factual audit of every news post and every Tally Insights lesson

Owner brief (condensed): Google Search Console reported **structured-data issues on
`/products/tallydrive`, `/services/tss` and `/products/silver`** - fix them. In the same pass the
**content must be 100% factual and correct**: no invented facts, no guessed menu paths, nothing that
can be contradicted by Tally's own documentation. Audit scope was set to the **widest** option - all
news posts and all 16 Tally Insights lessons, not just the three flagged pages.

Two standing constraints shaped the work:

- **The return policy is never published.** Licences are returnable in limited cases, with no time
  limit and no cooling-off window - but that policy is internal knowledge only and must not appear on
  the frontend or in an email to a customer.
- **No invented facts to satisfy a validator.** A Search Console "missing field" note is not
  permission to make something up.

Everything below was produced by reading the actual code/seed, not by assumption, and every content
claim was checked against Tally's own documentation before it was written.

### §1 - What Google flagged, and how each item was resolved

| GSC item | Verdict | What was done |
| :--- | :--- | :--- |
| `hasMerchantReturnPolicy` missing (all product pages) | **Omitted, permanently** | Licences *are* returnable, but there is no time limit and no cooling-off period, and the policy may not be published. `MerchantReturnNotPermitted` would be a false statement and `merchantReturnDays` has no honest value. The field stays absent - the cost is only a GSC *recommendation*, never an error, so price snippets keep working. |
| `shippingDetails` missing | **Omitted, permanently** | Every sellable item is a digital licence or subscription delivered by email. There is nothing physical to describe. |
| `priceValidUntil` missing | **Omitted, pending owner decision** | A date must not be guessed. Deferred with the pricing discussion. |
| `itemCondition` missing | **Added** | `https://schema.org/NewCondition` on every Offer - recommended, true for licence sales, zero risk. |
| **Offer/Product mismatch** on `/products/tallydrive` | **Fixed** | The Product node said *"TallyDrive Cloud Backup"* while its only Offer sold *"TallyDrive Extra Storage"*. The only priced row on that page **is** the storage pack - the 1 GB / 3 GB allowance is free with an active TSS and is described on-page as "Included with TSS", never sold. The node now describes exactly what the Offer sells (`TallyDrive Extra Storage (10 GB)`, sku `tallydrive-extra-storage-1yr`). |
| **Six indistinguishable Offers** on `/services/tss` | **Fixed** | Six unlabelled Offers on one Product could not be told apart. Every Offer now carries `itemOffered` with the plan's own name, taken from the same `lib/prices-catalog.mjs` row the pricing table renders, so the two cannot drift. |
| `aggregateRating` missing on `/products/silver` | **Left out, deliberately** | The 4.8/120 figure on that page belongs to **other** products in the "Most Popular Software" sidebar block - Silver is not in that list and has no rating of its own. Marking it up would be fabricated social proof. Waiting on the owner to confirm whether the 120 reviews are genuinely about Silver. |
| TSS marked up as a service, not a Product | **Kept as `Product`** | TSS is a Tally product that delivers a service; it has a fixed price, a duration and a SKU-like identity. Re-typing it would lose the Offer/price rich result for no gain. |

**Why this matters for the next person:** an absent field looks like an oversight in a code review.
The rationale therefore lives in a comment block directly above `productJsonLd()` in `lib/seo.ts`, and
§7 below adds a static guard so a future "fix" of these three omissions fails CI instead of quietly
turning the markup into a lie.

### §6 - New guard: `scripts/schema-audit.mjs`

A static, dependency-free audit (338 lines, no network, no build) - `npm run check:schema`, and the
**third** entry in `test:all` (h1 -> seo -> **schema** -> insights-svg -> ...).

Seven rule groups:

1. Exactly **one** Product builder exists (`lib/seo.ts`) - no page may hand-roll a second node.
2. `itemCondition: NewCondition` is emitted on every Offer.
3. `hasMerchantReturnPolicy`, `shippingDetails`, `priceValidUntil` appear **nowhere** in `app/` or
   `lib/` (comment-stripped, so the explanatory comment is allowed).
4. `aggregateRating` is emitted **only** on the allowlist (gold 4.8/120, server 4.7/85), the numbers
   must match the allowlist **and** must be visible on the page on a row naming that product.
5. Silver, TallyDrive and TSS must emit no `aggregateRating` - their 4.8/120 belongs to other products.
6. `/products/server` must emit no Offer (no price is shown); every other priced page must emit one.
7. Every Offer price derives from `payablePaise / 100`, never a literal; TallyDrive's node name must
   match its Offer; TSS Offers must carry `itemOffered`; `sku`s must be unique.

**Negative-controlled** (a guard that has never failed is not a guard):

| Mutation | Result |
| :--- | :--- |
| Injected `hasMerchantReturnPolicy: {}` into `lib/seo.ts` | **FAIL** - "must stay OUT of the markup" |
| Gave Silver an `aggregateRating` **and** a hardcoded `26550` | **FAIL x4** - not allowlisted, forbidden, price not derived, hardcoded price |
| Both files restored | PASS |

One real finding came out of writing it: the first version asserted the TallyDrive node name
*starts with* the Offer name, which failed because the Offer legitimately adds a duration qualifier
(`(10 GB)` vs `(10 GB, 1 Year)`). The check now compares the names with parentheticals stripped, so it
tests the intent - same item - without demanding identical strings.

### §11 - Don't break

- The three omitted Offer fields are **decisions, not TODOs**. Read the comment block above
  `productJsonLd()` in `lib/seo.ts` before "fixing" a GSC recommendation, and keep `check:schema` green.
- `aggregateRating` may only exist where the page **visibly** shows that product's own rating.
- `/products/server` must never gain an Offer while the page shows no price.
- Prices in markup must always derive from `payablePaise / 100` - the same server-authoritative figure
  the page renders.
- TSS facts have exactly one correct form; they are pinned in `scripts/sara-topics-test.mjs`. If Tally
  publishes a change, update the fact **and** the assertions together.
- News seed content stays ASCII-only, and a non-ASCII description has silently corrupted this file
  before.
