### §A — Architecture decisions

| Decision | Detail |
| :--- | :--- |
| Static curriculum, no DB | The whole curriculum lives in **one static TS module** — `lib/learn-tally-curriculum.ts` (`SECTIONS` + `LESSONS`). No Mongo, no admin screen, no migration. |
| One markdown engine, two surfaces | `lib/markdown-blocks.ts` = **pure parser** (headings, paragraphs, lists, pipe tables — no React, unit-testable in plain Node). `app/components/TallyInsights/MarkdownBody.tsx` = the **renderer** (real `<table>`, inline bold/code/link nodes). It carries **no `"use client"`**, so the *server* lesson page and the *client* hub both render identically. |
| Sidebar behaviour | Client-side section open/close using the CSS `grid-template-rows: 0fr → 1fr` transition (animates **both** directions) + inner opacity fade + `inert` on the collapsed panel. `activeSection` (content shown) was split from `openSection` (accordion open state) so a section can be collapsed without losing the reading position. Sticky at `lg:sticky lg:top-20`, **no inner scroll container** (that was the crop). |
| Content entry/exit | `displayLesson` state + an `isLeaving` phase: 170 ms fade-**out** → swap → fade-**in**. `key={slug}` replays the entry animation per lesson. |
| Animation fill-mode | The entry keyframe uses `backwards` (not `both`) — with `both` the animation's final `transform` permanently overrode the article card's `hover:-translate-y` lift. The exit uses `forwards`. |
| Reduced motion | `.insights-content-in` / `.insights-content-out` / `.insights-sidebar-section` all have `prefers-reduced-motion: reduce` opt-outs in `app/globals.css`. |

### §E — This session: the product-bar question, the broken dev server, and the build

**Owner question:** *"what's with that product bar tally-insights option not appearing in regular tab but only in incognito?"*

Diagnosis (measured, not guessed):

1. The **live site does not contain the item at all** — `curl https://sarvadnyainfotech.com/` → **0 occurrences** of "Tally Insights" (`x-vercel-cache: HIT`, `age: 1874`). The `Tally Insights` sub-item lives in `lib/product-nav.ts`, which was still **uncommitted/unpushed** at that moment. So the deployed product bar is correct — it simply cannot show an item that was never deployed.
2. The product bar (`app/components/Productbar.tsx`) is a **client component with fully static nav content** — since 2026-08-26 it imports `productItems` from `lib/product-nav.ts` directly (the old `/api/settings` fetch was removed), so there is **no API round-trip and no service worker** that could make a tab and an incognito window differ.
3. Therefore the regular-tab difference is the **Next.js client router cache / a stale tab**: a long-lived tab keeps the RSC payload it loaded before the change (soft navigations are served from that cache), while an incognito window has no cache and renders the fresh payload. **Fix for the user: hard-refresh (Ctrl+Shift+R) or close/reopen the tab.** Once this session's push lands, the item is on the live site for everyone.

**A real problem was found while investigating: the local dev server was returning HTTP 500 on every
route.** Cause: a **production `npm run build` had been run inside the main repo at 11:37** while
`next dev --turbopack` was running (started 10:35) — the exact hazard documented in AGENTS §9
("never run `npm run dev` and `npm run build` at the same time"). The production artifacts
(`BUILD_ID`, `export-marker.json`, `prerender-manifest.json`, `routes-manifest.json`) had been
written into the same `.next/` the dev server was using, so every route 500'd. Repaired by stopping
the dev process group, `rm -rf .next`, and restarting `npm run dev` → `/` returns **200** and the
product bar now contains "Tally Insights". **The build itself was then run in an isolated copy**
(`/tmp/opencode/build-check`, repo tar-copy + `cp -a node_modules`) so the owner's dev server was
never touched again: **`npm run build` → EXIT 0**, all 16 lesson routes prerendered
(`/tally-insights` ○ static, `/tally-insights/[section]/[lesson]` ● SSG with 16 paths).

#### §H4b — Owner-reported follow-up: *"mobile cersion card format is overflowing content and not aligned and not properly fited, wrap text"*

The first card layout was **measured broken**, not guessed at. The value cell was a **flex** container (`display:flex; justify-content:space-between`, label `flex: 0 0 40%`), but `renderInline()` gives a cell **several inline elements** (one `<span>` per text run, plus `<strong>` / `<code>` / `<a>`). In a flex container **every child element becomes its own flex item** with `min-width: auto`, so:

| Symptom (owner's words) | Measured cause |
| :--- | :--- |
| "not aligned" | The four inline fragments of one sentence became 4 separate flex items spread across the row by `space-between` — the label sat at the left, the sentence pieces floated apart. |
| "overflowing content" | Flex items cannot shrink below their **min-content** width → `scrollWidth - clientWidth` = **37 px** on the `Tally Prime (7.2)` cell of the comparison table, **clipped by the card's `overflow:hidden`** → text simply lost. |
| "not properly fited / wrap text" | Each fragment was its own box, so the sentence could never *flow* as a paragraph — it never wrapped, it only got cut. |
| "card format" | The label also ate a fixed 40 % of a 282 px card, squeezing a 120-character sentence into an 8-line narrow column. |

**Fix — the cell is a plain BLOCK again, and the column header is a caption ABOVE the value** (`app/globals.css`, `@media (max-width: 767px)` only):

| Change | WHY |
| :--- | :--- |
| `td` → `display: block` (the `display:flex` / `justify-content` / `gap` / `text-align:right` rules removed) | The inline markdown content flows as normal text again → it **wraps** as a paragraph instead of being torn into flex items. |
| `overflow-wrap: anywhere` on the cell (and on `code` / `a` inside it) | Long tokens — file paths, shortcut strings, URLs — **break** instead of pushing the card wide. |
| `::before` label → `display: block` caption with `margin-bottom: 0.25rem`, 11 px / 800 / `#475569`, **no** `flex: 0 0 40%` and **no** `text-transform: uppercase` | The value now gets the **full card width** on a 360 px phone (a long sentence is 2–3 lines instead of 8 cramped ones), and every caption starts at the **same left edge** so the pairs line up. Product names keep their real casing (`Tally Prime (7.2)`, not `TALLY PRIME (7.2)`). |
| Dead rule removed: `.insights-table .overflow-x-auto { overflow: visible }` | It targeted a **descendant** of the table, but the `overflow-x-auto` wrapper is the table's **parent** — the selector could never match. The wrapper stays as the desktop horizontal-scroll safety net. |

**Measured after the fix (360 px, comparison lesson)** — card 282 px wide; cells: title 13 px/800, caption 11 px/800 block, value 12 px flowing; `overflowPx` **0** and `clippedPx` **0** on **every** cell of all **19** tables (24 rendered tables across the 16 lessons, ~336 cells); **1** distinct caption left edge and **1** distinct right edge across all 18 non-title cells (perfectly aligned); card heights now 168 / 187 / 207 px where the same content previously overflowed and clipped. Desktop is untouched: at 768 px and 1440 px the table is still `display: table`, cells are `table-cell`, and the `thead` ("Feature") is visible with 9 rows × 3 columns.

**Note — the dev server had to be restarted.** Turbopack's file watcher did **not** pick up the `app/globals.css` edit on this mounted filesystem (`touch` did not help either), so the first re-probe still served the **old** flex CSS. `next dev` was stopped and restarted; the new rules were then confirmed **in the served stylesheet** (`overflow-wrap: anywhere`, no `display: flex`) before trusting any probe result. Always verify the served CSS, not just the file on disk.
