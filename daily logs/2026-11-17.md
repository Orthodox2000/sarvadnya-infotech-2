The retired `svd_diwali_2026` localStorage signal is gone. "Repeat visitor" now comes from the
admin's own session tracking: `VisitorProvider` writes the long-lived `svd_vid` cookie and

| File | Change |
| :--- | :--- |
| `lib/greeting-popup.ts` | Removed `GREETING_LEGACY_KEY`. Added `GREETING_SESSION_KEY`, `VISITOR_SESSION_COOKIE` (`svd_vid`, must stay in sync with VisitorProvider's `SESSION_COOKIE`) and `GREETING_RETURNING_GLOBAL`. `buildGreetingPreloadScript()` now (a) captures whether `svd_vid` already exists into `window.__svdGreetingReturning` **before hydration**, and (b) preloads the artwork for a new session only. |

### §8 — Greeting popup: slow, matching enter and exit

Owner: *"just a final minor change, that popup , entre smooth and slo , exit same slow aniamtion"*.

Previously the card entered in 300 ms and had **no** exit at all — `close()` set `open = false` and
the element unmounted on the next render. Now:

| | Backdrop | Card |
| :--- | :--- | :--- |
| enter | `animate-in fade-in` | `animate-in zoom-in-95 fade-in` |
| exit | `animate-out fade-out` | `animate-out zoom-out-95 fade-out` |

Both use `duration-700 ease-in-out` — one shared `GREETING_TRANSITION_MS = 700` constant in
`GreetingPopup.tsx` drives the class duration and the unmount timer, so the two directions cannot
drift. A `closing` state keeps the card mounted for the exit; `open` stays true so the scroll lock
and Escape handler remain in force until it is gone. `fill-mode-forwards` holds the final frame,
a timer ref makes repeat closes no-ops, cleanup cancels a pending timer on unmount, and
`prefers-reduced-motion` unmounts immediately. The CTA link still navigates without delay.

Isolated build after the change: compiled successfully, 173/173 pages, exit 0.

### §9 — Bug: 3rd+ visit never showed the popup (stale session flag)

Owner: *"as we foudn bug, if a person is 3rd time log in , they will always find flag down, so if
visitor comes and session exist, return flag to false , then set 20s timer as it garubnten even new
cvisitors ses that"*.

`GREETING_SESSION_KEY` is written `'1'` in sessionStorage at show time. sessionStorage survives
reloads in the same tab, so on the 2nd/3rd visit the old `if (sessionHandled) return;` fired before
the 20 s timer was ever scheduled — the visitor saw nothing. Fix in `GreetingPopup.tsx`:

1. Compute `returning` from `window.__svdGreetingReturning` (the `svd_vid` cookie captured in `<head>`) **before** the flag check.
2. If `returning`, write the flag back to `'0'` — then fall through to the timer branch. The 20 s popup is now guaranteed on every repeat visit.
3. The early return applies only when there is no visitor session yet but a stale flag exists.

`shownRef` still prevents a second card inside one page load (StrictMode-safe), and the skip list
plus its reveal-time re-check are untouched. Comments updated in `lib/greeting-popup.ts` and
`app/(site)/layout.tsx`. Isolated build: compiled successfully, 173/173 pages, exit 0.
