### §3 — Popup timing now follows the admin visitor session

The retired `svd_diwali_2026` localStorage signal is gone. "Repeat visitor" now comes from the
admin's own session tracking: `VisitorProvider` writes the long-lived `svd_vid` cookie and
`/api/identify` records that id in the `visitors` collection.

| File | Change |
| :--- | :--- |
| `lib/greeting-popup.ts` | Removed `GREETING_LEGACY_KEY`. Added `GREETING_SESSION_KEY`, `VISITOR_SESSION_COOKIE` (`svd_vid`, must stay in sync with VisitorProvider's `SESSION_COOKIE`) and `GREETING_RETURNING_GLOBAL`. `buildGreetingPreloadScript()` now (a) captures whether `svd_vid` already exists into `window.__svdGreetingReturning` **before hydration**, and (b) preloads the artwork for a new session only. |
| `app/components/GreetingPopup.tsx` | Reads the window global instead of the retired flag. New session (no cookie) → immediate popup; existing session → `GREETING_REVISIT_DELAY_MS` (20 s) timer. The flag is raised in **sessionStorage** at show time — once per browser tab session, not once forever — so a repeat visitor can see the card again in a later session. Reveal-time skip check retained. |
| `app/layout.tsx` | Preload-script comment updated. |
| `app/(site)/layout.tsx` | Popup-mount comment updated. |

Why the `<head>` capture matters: it runs during HTML parse, before `VisitorProvider` can create
`svd_vid` on a first visit, so the new/repeat decision cannot be corrupted by bootstrap. The skip
list (`/checkout`, `/demo`) and its reveal-time re-check are unchanged.

### §6 — Vercel rejected the push; footer JSX compile error found and fixed

Commit `f57978c` reached both remotes but Vercel reported `Vercel: failure`
(deployment `3wkQnVsupzMs5aPjgKJVjvicAP46`). Live probes still gave 404 on the DMS URL and the
homepage had **zero** `/modules/document-management` hrefs — the previous build was still serving.

reproduced the failure: `app/components/Footer.tsx` had an unclosed `<br>` in the newly changed
landline line — `+022-4974 2200 <br> +022-4964 7959` — which SWC rejects with
*"Expected '</', got 'jsx text'"*. This was inherited from the uncommitted 2026-11-16 Footer edit
that this session committed.

Owner then clarified the intended rendering: *"i want that br and landline spper on seprate lines
no / between"* — the two landlines on separate lines with no slash separator. Fixed by replacing
the single anchor with two `block` `<a href="tel:…">` anchors (`+912249742200` and
`+912249647959`), one number per line, each independently dialable. No `<br>` and no `/` remain.
