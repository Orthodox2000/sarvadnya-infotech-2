## ✅ ADDENDUM (same day) — GSC "Video thumbnail is transparent" FIXED

**Report:** Google Search Console — Video Indexing — "Thumbnail is transparent", first detected 21/09/2026, page `https://sarvadnyainfotech.com/`, video `https://sarvadnyainfotech.com/sarvadnya-mobile.mp4` (last crawled 20 Sept). **Was NOT previously fixed** — the 2026-09-08/09-11/09-16 changes (VideoObject removal, X-Robots-Tag noindex on .mp4, robots disallow) addressed "not on a watch page" / dropping raw mp4 URLs, never the thumbnail opacity.

**Root cause (evidence-based, systematic-debugging):**
- `HomeHero.tsx` sets `poster="/video-thumbnail.png"` on both `<video>` tags (mobile + desktop).
- `public/video-thumbnail.png` PNG header: width=1280 height=720 bitdepth=8 **colortype=6 = Truecolor RGBA** — alpha channel present. Google rejects ANY RGBA thumbnail as "transparent" regardless of actual pixel content (sampled: 3476 opaque / 124 semi (edge antialiasing) / 0 fully-transparent — image LOOKS opaque but format is RGBA).

**Fix (commit pushed):**
- Converted poster to **opaque JPEG**: `public/video-thumbnail.jpg` (1280×720, Format24bppRgb = no alpha, 50,022 bytes, flattened onto the site cream `#FBFAF6` so edge antialiasing stays clean; System.Drawing, quality 92).
- `HomeHero.tsx` both `poster` attrs → `/video-thumbnail.jpg` + `// CHANGE: 2026-09-22` comment.
- Deleted the now-unreferenced `public/video-thumbnail.png` (grep: zero runtime refs; only historical docs mention it).
- Verified: JPEG magic `FF D8`, Format24bppRgb confirmed via System.Drawing; `npm run typecheck` exit 0.
