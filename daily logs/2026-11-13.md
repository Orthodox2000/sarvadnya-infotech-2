### §1 — What "audit" meant here

| Pass | What it answers |

| **Type check** (`npm run typecheck`) | Does every import still resolve? Did a shared file drift between the two forks? |
| **Static guards** (`check:h1`, `check:seo`, `check:schema`, `check:alt`, `check:demo`, `security:check`) | Are the site-wide rules (one H1, share image, computed ratings, alt text, cart/demo isolation, write-route limits) still honoured? |
| **Deterministic suites** (`test:*`) | Do the pure-logic pieces — cart math, payments, status history, Sara guards, referral codes, drafts — still behave? |

No dev server was started, so nothing was written to the live database (§2.2 of `AGENTS.md`).

### §3 — Why the brand rule matters enough to fix one class name

`green-*` and `emerald-*` were retired as the brand when the site moved to teal `#006569`. A single
`emerald-600` link renders in a *different green* next to teal buttons on the same screen, so it reads
as a mistake. Every hit found is now `teal-700` (the solid-button step). WhatsApp `#25D366` was left
alone — that green is deliberate and is not the brand.

### §4 — Why the active sidebar icon was invisible

The nav row lights up teal when you are on that screen, and the icon inside it kept its own teal
colour, so it disappeared into the background. The icon is now `text-white`, i.e. it inherits the same
contrast as the label beside it.

### §6 — Why `npm update` and not the newest numbers

`npm update` only installs versions the existing `package.json` ranges already allow, so no major
version changed and no code had to be rewritten. The one upgrade worth naming is **Next 15.5.29**,
which closes the critical advisory `npm audit` was reporting on both repos.

**Next 16 was deliberately not adopted.** In this public repo `proxy.ts` is a *dormant* admin guard —
Next 15 does not read that filename, so it does nothing. Next 16 is the release where `proxy.ts`
becomes the real middleware file, which would switch an admin guard on inside the **public**
deployment. The two repos therefore stay on 15 together.

Versions were read back from `package-lock.json`, never from `node_modules` (that folder drifts ahead).

## Session 3 — The admin dashboard, remade

### §8 — What was wrong with the old one

It answered *"how many of each thing exist"*. It never answered *"what needs me right now"*, which is
the only question an owner opens a dashboard to ask. Every tile was a dead counter — seeing
"TSS Renewals: 12" told you nothing about whether 12 was fine or an emergency.

### §9 — What it is now

| Block | What it shows | Why |
| :--- | :--- | :--- |
| **Headline KPIs** | unique visitors, new leads (24 h), orders, revenue collected | the four numbers worth seeing without scrolling |
| **Needs attention** | TSS renewals waiting, orders awaiting payment, bug reports (24 h), new leads (24 h) | the queue: each row is a link straight to the screen that clears it |
| **System health** | email ledger / capture / DB state | if something silently stopped working, this is where it shows |
| **Three metric groups** | Leads & Inquiries · Engagement · Commerce & Careers | the old list, grouped so related numbers sit together |
| **Recent orders / recent leads** | the latest rows, with status and time | lets you spot a live order without leaving the page |
| **Quick links** | the screens you actually open | one click instead of the sidebar |

Also added: loading skeletons (the page no longer flashes empty), an error banner with a **Retry**
button (before, a failed fetch left a blank dashboard with no explanation), and relative timestamps
("3 min ago") instead of raw digits.

Every tile is now a **link**, and everything is teal — no second accent colour.

### §10 — The stats API behind it

`app/api/admin/stats/route.ts` was rewritten:

- **Parallel queries** (`Promise.all`) instead of one wait after another, so the dashboard is faster.
- **New fields, nothing removed.** The dashboard needed 24-hour and 7-day deltas, pending counts,
  revenue, and the recent rows. Existing keys were left untouched on purpose: `scripts/api-test.mjs`
  and `scripts/visitors-admin-test.mjs` assert against the old shape, and breaking them to gain a
  field would be a bad trade.
- **Read-only.** No collection, index or write changed.

Two rules were preserved deliberately:

- `visitorsLast24h` still windows on **`lastSeen`**, not `firstSeen`, so a returning visitor counts.
  It therefore always equals the Visitors screen's own "active today".
- **Site Visitors** still means **unique humans**, so crawlers cannot inflate the headline number.

### §11 — Payments summary (the owner's own in-progress file)

There was an uncommitted change in `app/admin/payments/summary/page.tsx`. It is kept. One thing in it
needed a nudge: the new **"Transaction Initiated"** total counted exactly the same rows as an existing
total, so two cards always showed one number. It now counts rows that carry a **`razorpayOrderId`** —
i.e. orders that actually reached Razorpay — which is what the label says. Its `emerald-600` also
became teal.

## Session 4 — Environment documentation

### §12 — What was added

| File | Added |
| :--- | :--- |
| `.env.example` (root) | `SITE_URL`, `MEGA_ENABLED`, `NEXT_PUBLIC_WHATSAPP_PHONE`, `NEXT_PUBLIC_MAP_IFRAME_URL`, `BASE_URL` |
| `sarvadnya-advanced/.env.example` | `MEGA_ENABLED`, `VISITOR_IGNORE_IPS`, `EMAIL_DESTINATION_RECIPIENTS` / `EMAIL_FORM_RECIPIENTS` / `EMAIL_CC_ENABLED` / `EMAIL_CC`, `AUTO_REPLY_ENABLED`, the two `NEXT_PUBLIC_` vars, `BASE_URL` |

Two of these are traps worth writing down, and both are now in the file:

- **`VISITOR_IGNORE_IPS`** — the admin tree has no development database either, so testing the panel
  records real visitors in the live collection unless your address is listed.
- **`BASE_URL`** — the admin repo's test scripts must point at `advanced-sarvadnya.vercel.app`, not the
  public site (its `/api/admin/*` routes only exist on the admin deployment). Also: each script re-reads
  `.env` and **overwrites** an inline value, so `BASE_URL=… npm run test:all` silently does nothing.

The admin file is **CRLF**; it was edited in place and the line endings were re-checked afterwards.
