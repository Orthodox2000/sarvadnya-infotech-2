### What was built

A per-account **referral code** for every `/careers` member: each user gets a unique 8-character
code, can share it via a `?ref=` link, and sees how many people signed up with it. Attribution is
**fixed at signup and never editable** (owner ruling) — display-only on the profile card.

| Piece | Detail |
| :--- | :--- |
| `lib/careers-referral.mjs` + `.d.mts` | **Single source of truth** for the code format. Pure ESM, zero deps, isomorphic — randomness comes from `globalThis.crypto.getRandomValues` (browser AND Node ≥ 19), so the SAME module is imported by the signup route (server) AND `AuthForms` (client bundle, whose `?ref=` filter uses the shared alphabet). Alphabet = **32 chars**: `A-Z` minus `I`/`O` plus `2-9` minus `0`/`1` (no ambiguous pairs, safe to read aloud). Length **8**. Exports `REFERRAL_ALPHABET`, `REFERRAL_CODE_LENGTH`, `normalizeReferralCode` (uppercase + strip non-`A-Z0-9`; deliberately KEEPS `0/1/O` so a bad code fails loudly instead of being mangled), `isValidReferralCodeFormat`, `generateReferralCode`, `generateUniqueReferralCode(isTaken, attempts=10)`. Hand-written `.d.mts` mirrors `lib/email-autoreply.d.mts` (types without a build step). |
| `app/api/auth/careers/signup/route.ts` | (1) **Rate limiting added** — careers auth had NONE; per-IP fixed window **20/min** BEFORE parsing the body (like the cart order route). (2) Optional `referralCode` is normalised + format-checked + must exist on a real account, else `400 { code: 'INVALID_REFERRAL' }`. (3) Every new account gets its OWN unique code (collision-checked via `findOne`). (4) Persists `referralCode` + `{ referredBy, referredAt }` when referred. (5) Lazy `ensureReferralIndexes()` — **partial unique** index `careers_users_referralcode_unique` (only docs that HAVE a code participate, so pre-referral docs never conflict) + `careers_users_referredby`. Index failure is logged and swallowed (the generator's own collision check degrades gracefully). |
| `app/api/auth/careers/login/route.ts` | **Lazy backfill**: a pre-referral account gets a code the moment it logs in, so the profile card can never render empty. Returns `referralCode` + `referredBy` in the serialized user. |
| `app/api/auth/careers/me/route.ts` | Unchanged — already returns the full user doc minus `passwordHash`, so `referralCode`/`referredBy` flow to the client automatically. |
| `app/api/auth/careers/referral-stats/route.ts` | **NEW.** Auth-gated (`getCurrentCareersUser`), read-only `countDocuments({ referredBy: code })`. Exposes **only the count** — never WHO was referred (no candidate PII leaks to a member). Returns `{ ok:true, referralCode:null, referredCount:0 }` for a code-less account. |
| `app/components/careers/ReferralCard.tsx` | **NEW.** Shows the member's code (mono, wide tracking) + **Copy code / Copy link / Share** (Web Share API, with a clipboard fallback for non-secure contexts and an `execCommand` fallback for old engines) + the referred count line + a "You were invited with code X" footer when `referredBy` is set. **Hydration-safe:** `window.location.origin` is only ever touched inside click handlers, never during render; `copyFailed` becomes a manual-copy hint. Renders `null` when there is no code. |
| `app/components/careers/IdCard.tsx` | Mounts `<ReferralCard user={user} />` with the other account settings (used on `/careers` AND `/careers/profile`). |
| `app/components/careers/AuthForms.tsx` | **`/careers?ref=CODE` auto-fill** — read in an effect (never during render, so URL access cannot desync SSR/hydration); a well-formed code **reveals the referral field prefilled AND switches to the Sign-Up view** (a referred visitor by definition has no account); a malformed `ref` is silently ignored. A **"I have a referral code"** toggle hides the field by default. The input filters to the shared alphabet as you type (max 8). After **3 consecutive server rejections** of a well-formed-but-unknown code, an amber **"Continue without referral"** card appears (also appears immediately on a malformed submit) which re-submits with `skipReferral`. On a successful signup the `?ref=` param is stripped from the URL so a refresh cannot re-prefill it. |
| `lib/careers-auth.ts` | `CareersUser` gains `referralCode?`, `referredBy?`, `referredAt?`. |
| `scripts/backfill-referral-codes.mjs` | One-time **idempotent** backfill for accounts that existed before the feature. **Dry-run by default**, `--apply` writes codes + creates the indexes. Only users missing a well-formed code are touched, guarded so a concurrent signup/login can never be overwritten. PII-light logs (`ab●●●@domain`). Header documents the **production-URI override** (the local `.env` is NOT the deployed DB — AGENTS §18). |
| `scripts/referral-code-test.mjs` | **19 assertions** on the pure module: alphabet size/uniqueness/ambiguity, generator length/uppercase/collision-free across 5,000/dimension coverage, format gate (length/case/ambiguous/punctuation/non-string), normaliser behaviour, and the unique-generator retry/throw/predicate checks. |
