### Workstream I: Production diagnosis — "Blob isn't connecting on prod" (afternoon)
**Symptom:** Uploads (admin images / career resume) returned `500 Cloud storage upload failed. Please check your credentials.` on the deployed site while working locally.

**Diagnosis performed (detailed):**
1. Confirmed `.env` is **gitignored** (`git check-ignore .env` → matched; not tracked by git). Vercel never receives any of its contents.
2. Verified the local credentials are **valid**, not expired — ran live round-trips against the store with the token from `.env`:
   - `list({ prefix: 'sarvadnya' })` → OK (0 blobs)
   - `put('sarvadnya-test/connectivity-check.txt', …)` → OK, URL `https://7nmnibqapet2upei.public.blob.vercel-storage.com/…`
   - `get(url, { access: 'public' })` → streamed back "hello prod test"
   - `del(url)` → OK
3. Audited the SDK usage against the installed `@vercel/blob@2.5.0` types: `get()` returns `{ stream: ReadableStream, blob }` (so `result.stream.getReader()` is correct), `del()` accepts `string | string[]`, and `put()` supports `ReadableStream` bodies with `duplex: half` — the chunk-assembly logic is sound.
4. Root cause: `BLOB_READ_WRITE_TOKEN` (and `BLOB_STORE_ID`) exist **only** in the gitignored local `.env`. On Vercel the SDK throws `No blob credentials found. Pass a token option, set BLOB_READ_WRITE_TOKEN, or use oidcToken…`, which the route's generic catch mapped to the misleading 500 message.

**Fixes applied:**
| # | File | Change |
|---|------|--------|
| 1 | `.env.example` | Documented `BLOB_READ_WRITE_TOKEN` + `BLOB_STORE_ID` with a CRITICAL note that they must be added to the Vercel project environment (Dashboard > Settings > Environment Variables) for Production — the local `.env` never reaches the deployed site. |
| 2 | `lib/chunkUpload.ts` | Catch block now logs an explicit "BLOB_READ_WRITE_TOKEN is not set" diagnostic (with instructions) when the token env var is missing, so Vercel function logs show the true cause instead of a generic error. |
| 3 | `next.config.js` | Removed `microphone=()` from the `Permissions-Policy` header. This policy was **also blocking the brand-new voice-input feature on prod**: with `microphone=()` the browser denies `SpeechRecognition`, so Ask Sara's mic button could never start. (Verified CSP/connect-src already allow `https://*.public.blob.vercel-storage.com`.) |

**User action required (no code change can ship the secret):**
- Add `BLOB_READ_WRITE_TOKEN=vercel_blob_rw_7nmnIBQAPeT2upEI_…` and `BLOB_STORE_ID=store_7nmnIBQAPeT2upEI` to the **Vercel production** environment (easiest: `npx vercel env add` / `npx vercel blob add`). Without this, uploads on prod keep failing until the token is present. If `MONGODB_URI`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `ADMIN_ACCESS_KEY` are also absent on Vercel, the site's other features will fail the same way — worth auditing all of them.
