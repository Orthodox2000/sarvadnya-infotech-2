### 8. News marquee (ticker) speed fix (`app/components/NewsFeed.tsx` + `app/globals.css`)
- **Problem (3 reporting rounds):** the top news ticker scrolled "too fast". Root cause discovered in round 3: the old CSS used `animation: news-ticker-scroll 60s linear infinite !important` — a **fixed 60s** for a fixed list, so when the seeded blog grew the list from 3→13 items the same 60s covered ~3× the track width ≈ 118 px/s (severe). Earlier attempts (measuring width ÷ 65/45 px/s, setting the duration via an inline `--news-ticker-duration` custom property) **never took effect** because (a) the `!important` shorthand can't be overridden by a non-`!important` inline variable, and (b) even after splitting into separate animation properties, the one-shot measurement ran before `offsetWidth` was non-zero and bailed to the default.
- **Final fix (round 3):**
   - `app/globals.css` — the `.animate-marquee-infinite` class now carries only layout + GPU hints (display:flex, width:max-content, will-change, backface-visibility, perspective). All animation properties moved to **inline style** in the component, so nothing can override them.
   - `app/components/NewsFeed.tsx` — the track's inline `animation` is set to `news-ticker-scroll ${tickerDuration}s linear infinite`. Duration is measured with a **`ResizeObserver`** on the `[data-ticker-group]` element (fires automatically once layout happens, plus on any size change / font load) → `duration = offsetWidth ÷ 30 px/s`, clamped to ≥15s. Guard: only updates when the change is >5% to avoid mid-scroll jumps; initial state 200s so even the pre-measure frame is never fast.
   - **Constant speed guarantee:** 30 px/s regardless of how many news items exist — the duration is recomputed automatically whenever `newsItems.length` changes (admin adds/removes posts) or the viewport resizes.
