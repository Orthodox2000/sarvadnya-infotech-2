### §2 - What this session added

**1. Account-created welcome mail.** `lib/email-careers.mjs` gained `ACCOUNT_CREATED_SUBJECT` and
`buildAccountCreatedHtml({ name, email, referralCode, loginUrl, company, logo })`; `lib/email-careers.d.mts`
gained the matching declarations. It greets by first name, states the address the account is registered to,
shows the referral code the account was just issued, and carries a **Sign in** button whose href is passed
through `safeUrl()` (a `javascript:`/`data:` URL is refused and the button falls back to the on-site
`/careers/login`). No internal fields.

**2. Wired into signup.** `app/api/auth/careers/signup/route.ts` sends it after the session cookie is set, in a
`try/catch` that logs and swallows: the account already exists, so a mail failure must never fail signup. It
uses `sendTemplatedEmail()` rather than `sendEmailDirect()` on purpose — a duplicate address returns **409
before** this point, so signup is inherently once-per-address and does not need the `email_queue` ledger, and a
candidate copy must not depend on the company `careers` recipient being configured.

**3. Password-reset OTP repaired.** `lib/email-otp.ts` was **dead in production**: it built `new
Resend(process.env.RESEND_API_KEY)` at module load and returned early unless `AUTO_REPLY_ENABLED` was set —
but that variable is the *marketing thank-you* kill-switch and is unset in `.env`, so every reset code was
silently discarded. It now takes the key and sender from `getEmailConfig()` (admin-managed, same as every
other mail), drops the marketing gate, escapes the OTP, and throws on a Resend error so the caller's existing
`console.warn` fires. It is **deliberately not** routed through `sendTemplatedEmail()`: that path applies the
global CC, which would leak a one-time code to a third party.

**4. Recipient is HR.** `scripts/seed-careers-recipient.mjs` now writes `hr@sarvadnyainfotech.com`.

**5. Dead route deleted.** `app/api/careers/apply/route.ts` accepted a job application, only `console.log`ed
it, and had **zero importers** — the real flow is the `submitApplication` server action behind
`QuickApplyModal`. Deleted rather than left as a trap.

**6. Test suite extended.** `scripts/careers-email-test.mjs` grew to **34 assertions**: the account-created
template is covered for first-name greeting, address, referral code, login href + `javascript:` refusal,
hosted-logo fallback, no internal fields, escaping, and no `AUTO_REPLY` gate. It also joins the
"no template prints `undefined`/`[[` markup" sweep.

### §7 — Where the brochures live, and why not Blob

The owner offered two homes: **Blob** or **directly from the server**. They were put in
`public/brochures/` — the second option — for four reasons:

1. A file in `public/` is **versioned with the code**. A Blob upload is not in git, so a rollback or a
   fresh clone would not reproduce the site.
2. No `BLOB_READ_WRITE_TOKEN` is needed, no upload step, no signed URL, no expiry.
3. Next/Vercel serves it with the correct `Content-Type: application/pdf` and supports range requests,
   which is what a PDF viewer needs for a 7.7 MB document.
4. The files are already in the repo tree; moving them to Blob would add a network dependency to a
   static download for no benefit.

They are **not** optimised/compressed in this session: the source PDFs are the owner's designed
documents and re-encoding them would change the artwork.
